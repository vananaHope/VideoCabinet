# 화면 계층을 Qt 안의 웹 UI(React + shadcn/ui)로 만들고, 재생은 mpv로 유지한다

첫 버전의 Qt 위젯 화면은 다크 테마와 정리(#32)를 거친 뒤에도 투박하다는 평가를 받았다. 위젯 스타일시트로는 카드, 격자, 빈 상태 같은 현대적인 구성을 낼 수 있는 폭이 좁다. 그래서 ADR-0001의 화면 부분만 바꾼다.

- 재생 엔진(mpv)과 Python 앱 코어는 그대로 둔다. 화면 계층만 교체한다.
- 앱 창은 계속 PySide6다. 재생 외 화면은 그 안의 `QWebEngineView`에 띄우는 React + TypeScript + Tailwind v4 + shadcn/ui 웹 UI로 만든다.
- 웹 UI는 `QWebChannel`로 앱 코어의 공개 메서드만 호출한다.
- 재생 화면은 HEVC·AC3·DTS를 재생해야 하므로 지금처럼 네이티브 mpv 위젯을 쓰고, 웹 화면과 바꿔 보여 준다.

디자인이 깨지는 것을 막기 위해 `@shadcn/lint`의 규칙 6개를 모두 오류로 켠다.

- `no-restyle`, `no-raw-colors`, `no-arbitrary-values`, `no-inline-styles`, `no-unknown-classes`, `require-static-classes`
- 웹 UI 변경은 lint·타입 검사·빌드를 통과해야 완료로 본다.
- 색·간격·둥글기는 테마 토큰으로만 정한다. 특별한 모양은 사용하는 곳에서 덮어쓰지 않고, 변형(variant)을 가진 전용 컴포넌트로 만든다.

빌드한 웹 파일은 앱과 함께 배포하며, 실행 중 네트워크나 CDN에 기대지 않는다. 독립 실행 파일 빌드는 이 결정을 전제로 따로 정한다.

## Considered Options

- **Qt 위젯 유지 + Fluent 계열 위젯 라이브러리**: 가장 싸지만 구성의 자유도가 낮아 투박함이 크게 줄지 않는다.
- **Electron/Tauri로 전면 교체**: ADR-0001에서 기각한 이유(mpv를 창에 넣기 어렵고, 트레이·프로세스 관리를 새로 짜야 함)가 그대로 남는다.
- **Ant Design**: 다크 테마가 기본 제공되지만 관리자 화면 인상이 강하다. 사용자가 shadcn/ui와 lint로 디자인을 강제하는 쪽을 골랐다.

## Consequences

- 개발과 준비 절차에 Node가 더해진다.
- 앱 크기는 Qt WebEngine만큼 커지고, 메모리는 150~300MB쯤 늘어난다.
- 키보드 조작 규칙(창이 앞에 있을 때만, 예약 키, `Ctrl+1`~`Ctrl+7`)은 웹 화면에서도 같게 맞춰야 한다.
- 전환은 시험판(라이브러리 페이지 하나)으로 다음을 확인한 뒤 페이지별로 진행한다.
  - mpv 전환
  - 키보드만으로 조작
  - 한글 IME
  - 시작 속도와 메모리
  - 대량 목록 성능

## 시험판 결과

라이브러리 시험판에서 mpv 왕복과 선택·스크롤 복원, 예약 키 처리를 확인했다. 5,000개 목록에서도 가상 격자는 약 60fps를 유지했으며, 웹 측정 중 Qt 스레드를 폴링하면 프레임 간격이 늘어나는 측정 오류를 제거했다. 시작 비용은 Qt보다 약 0.4초 늘었다.

교차 검토의 빈 창·빈 WebEngine 비교에서 Chromium의 고정 작업 집합 비용은 약 210MiB였다. 이미지 캐시 등 사용 누적 비용이 추가되므로 앞서 예상한 150~300MB를 총 증가량의 상한으로 보지 않는다. 이 수치는 당시 Qt/웹 시험판을 비교한 기록이다.

## 웹 기본 전환 결과 (#55, 2026-10-15)

모든 탭과 업무 대화상자를 단일 웹 셸에서 열도록 전환하고 Qt 대체 화면과 실행 스위치를 제거했다. Qt에는 셸 창·WebEngine 호스트, mpv 재생 화면, 트레이, 파일 선택과 공용 오류/종료 경고만 남긴다. 비교용 Qt 모드 없이 웹 기본 경로로 검증한다.

Windows에서 README의 `scripts/setup.ps1`로 준비하고, 1100×720 실창·로컬 production 빌드·24개 합성 영상/썸네일을 사용해 별도 프로세스로 3회 측정했다. `scripts/check_web_library.py --count 24 --no-screenshots`의 시작 시간은 스크립트 진입부터 Python import·코어 준비·첫 React 렌더·두 프레임과 250ms 안정화 대기까지 포함한다. 실제 사용자 라이브러리의 콜드 스타트나 순수 페인트 시간과는 다르다.

| 측정 | 시작 시간(ms) | 작업 집합(MiB) | Private commit(MiB) |
|---|---:|---:|---:|
| 1 | 2398.98 | 463.27 | 396.28 |
| 2 | 2320.86 | 459.98 | 394.61 |
| 3 | 2380.16 | 465.97 | 402.18 |
| 중앙값 | 2380.16 | 463.27 | 396.28 |

메모리는 시작 직후 값이 아니라 목록 갱신 5회·스크롤 120프레임 뒤 Python과 자식 `QtWebEngineProcess`의 `WorkingSet64`/`PrivateMemorySize64` 합계다. 측정용 PowerShell 프로세스는 제외했다. 이전 시험판과 입력·검사 조건이 달라 증감 비교로 해석하지 않는다.

데스크톱 잠금 안에서 탭·예약 키, 실제 mpv 재생 왕복, 웹 대화상자, 검색·모아보기, 대기열, 폴더·설정, 통계와 재생 중 `Alt+S`를 확인했다. 메뉴를 닫으면 재생이 유지되며 **키 배치…**를 선택하면 정상적으로 시청을 종료·저장하고 웹 설정의 키 배치 구역으로 이동한다. 실제 한국어 IME 후보 선택, 배율·다중 모니터 포커스, OS 트레이 메뉴 클릭, 장시간 재생·왕복의 메모리 추이는 사람이 추가 확인한다.
