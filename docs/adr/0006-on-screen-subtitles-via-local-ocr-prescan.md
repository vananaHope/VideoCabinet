# 화면 자막은 로컬 Windows OCR로 영상 전체를 미리 훑어 만든다

영상에 입혀진 외국어 글자(예능의 박힌 자막 등)를 번역하기 위해, 사용자가 정한 **화면 자막 영역**을 영상 전체에 걸쳐 로컬 Windows OCR로 읽는다.
같은 글자가 이어진 구간을 시각 붙은 줄(**화면 자막**)로 저장하고, 기존 번역 흐름으로 **화면 번역 자막**을 만든다.
재생 중 실시간으로 읽고 번역하지 않으며, 화면 이미지를 구독 CLI에 보내지도 않는다. 2026-10-26 사용자 결정이다.

## Considered Options

- **재생 중 실시간 번역(MORT 방식)**: 영역을 계속 읽고 글자가 바뀌면 번역한다. 기각했다.
  이 앱의 번역은 `codex exec`·`claude -p`를 매번 띄워 한 번에 수 초~수십 초가 걸린다. 빠른 OpenCode Go도 1~3초 걸린다.
  박힌 대사는 한 줄이 2~4초 떠 있으므로 번역이 대사보다 늦게 나온다. 사용자는 자동 일시정지를 원하지 않았고,
  결과를 저장하기를 원했다. 한 줄씩 번역하면 문맥과 용어집도 쓸 수 없다.
- **구독 CLI에 화면 이미지 보내기(비전 LLM)**: 꾸민 글씨를 잘 읽지만 영상 한 편에 수천 장을 처리해야 해서
  속도와 구독 한도를 감당할 수 없다. 화면 한 장만 번역하는 후속 기능에는 여전히 맞는 방식이다.
- **PaddleOCR·EasyOCR**: 한중일 인식이 더 좋지만 수백 MB 의존성이 붙어 설치 크기를 줄이는 방향과 반대다.

## Consequences

- 글자를 읽는 단계는 ADR-0003의 "구독 CLI" 원칙의 예외다. 번역 단계는 그대로 구독 방식(ADR-0003·0005)을 쓴다.
- 읽을 언어의 Windows 언어 팩이 설치되어 있어야 한다.
- 인식률은 미리 시험하지 않는다. 비슷한 실시간 번역기 MORT도 Windows OCR을 기본으로 쓰기 때문이다(2026-10-26 사용자 결정).
  대신 OCR 엔진을 교체할 수 있는 경계 뒤에 두어, 꾸민 텔롭 등에서 부족하면 그 경계의 구현만 더해 다른 엔진으로 바꾼다.
- 영상마다 처음 한 번은 자막 대기열에서 훑기를 기다려야 한다. 그 대신 재생할 때 시각이 정확히 맞고 검수·검색·내보내기를 쓸 수 있다.
- 위치가 장면마다 바뀌는 텔롭은 영역 방식으로 잡지 않는다.
