# 자주 나온 검토 지적

#43~#66의 교차 검토 보고서(`.local/orchestration/issue-*/review*.md`)에서 반복해 나온 지적을 유형별로 모았다. 구현자는 제출 전에 이 목록으로 스스로 점검하고, 검토자는 이 목록을 먼저 확인한다. 새 유형이 두 번 이상 나오면 관리자가 여기에 더한다.

## 1. 테스트가 보증을 잃는다

- 매개변수 테스트의 입력 목록이 비어 테스트가 통째로 건너뛰어진다. 예: `NATIVE_PAGES`가 비어서 셸 알림 테스트가 사라짐(#51, #53).
- 단언이 실제 조건 없이도 통과한다. 예: hover되지 않았는데 hover 대비 단언이 통과(#43 R3), 가드가 없어도 "조합 중 Enter 방지" 확인이 통과(#43 F9).
- 기존 테스트나 실창 검사를 다른 모드로 바꾸거나 고정 값에 묶어, 원래 지키던 동작을 더는 지키지 않는다(#58 N2, #58 1, #51 중요 1).
- **점검**: 바꾸거나 옮긴 테스트마다 "이 테스트가 지금도 실패할 수 있는가"를 확인한다. 일부러 동작을 깨뜨려 테스트가 실패하는지 한 번 본다. 건너뛴 테스트 수(`-rs`)가 늘었으면 이유를 적는다.

## 2. 같은 일을 여러 번 한다 (성능)

- 재생할 때마다, 탭에 들어올 때마다 목록이나 숨은 위젯을 다시 만든다(#49 중요 1, 사소 2).
- 같은 결과를 두 번 직렬화하거나 같은 JSON을 두 번 보낸다(#49 중요 2).
- 무거운 SQL을 읽기 트랜잭션 안이나 메인 스레드에서 돌린다(#52 I1, #47).
- **점검**: 5000개 규모 데이터로 진입·재생 복귀·갱신 경로를 한 번씩 재 본다. 호출 횟수를 세서 같은 계산이 한 동작에 두 번 이상 일어나지 않는지 본다.

## 3. 데이터가 많거나 길 때 배치가 무너진다

- 기본 창 1100×720에서 항목이 1~3개만 보이거나 버튼 일부가 가려진다(#43 F2, #48 F3·F4, #51 사소 3).
- 긴 텍스트가 말줄임 없이 잘리거나, 개수 표시(`+N`)가 없다(#46 F3, #43 F3).
- 내용이 적은데도 빈 스크롤 막대가 보인다(#43 R5, #48 F5).
- **점검**: 데이터 0개·적음·최대·긴 텍스트 네 경우를 1100×720 offscreen 스크린샷으로 직접 열어 본다.

## 4. 디자인 토큰과 변형 규칙을 어긴다

- 정해진 색 규칙과 다른 색을 쓰거나(#48 F1), 선택 상태에서 배지·칩 배경이 사라진다(#48 F2, #49 사소 4).
- shadcn 컴포넌트 대신 원시 요소에 직접 스타일을 준다. lint가 못 잡는다(#43 F8).
- **점검**: 특별한 모양은 사용하는 곳에서 덮어쓰지 않고 컴포넌트 변형으로 만든다. 선택·hover·포커스 상태 스크린샷을 따로 본다.

## 5. 상태가 남거나 늦게 바뀐다 (수명)

- 이전 목록이나 완료 문구가 다음 동작 전까지 남는다(#48 F6, #49 새 결함 1).
- 재생에서 돌아오면 원래 탭이 아니라 기본 탭으로 간다. 트레이 복원 때 다른 탭이 잠깐 보인다(#58 2·N3).
- 페이지가 보이거나 숨는 시점을 모르고 계속 갱신한다. 1초 타이머가 숨은 페이지에서도 돈다(#58 3, #51 사소 5).
- 앱 종료 중 작업자 신호가 지워진 객체로 간다(#52 S2).
- **점검**: 진입 → 동작 → 재생 → 복귀 → 다시 진입, 그리고 트레이 숨김·복원과 종료를 한 번씩 거쳐 화면 상태를 확인한다.

## 6. 키보드·포커스·단축키 범위가 틀린다

- 재생 중 셸 단축키(`Alt+S` 등)가 시청을 끝낸다(#51 중요 2).
- 모달 중 단축키 차단이 너무 넓어 프로그램이 시작한 이동까지 막는다(#53 N-1). Esc가 안쪽 후보 목록보다 대화상자를 먼저 닫는다(#53 I-2).
- 시작 포커스나 메뉴를 닫은 뒤 포커스가 원래 자리로 돌아오지 않는다(#43 F4·F5).
- **점검**: 키 입력에서 시작된 동작과 프로그램이 시작한 동작을 나눠서 막는다. 모든 새 화면에서 시작 포커스, Tab 순서, Esc, 예약 키(`Ctrl+1`~`Ctrl+7`, `Alt+S`, `F1`)를 확인한다.

## 7. 기존 동작과 달라진다 (동등성)

- 상태 문구, 꼬리표 우선순위, 키 표시 형식이 이전 화면과 다르다(#49 사소 7, #51 N2, #51 사소 2).
- 이전 화면에 있던 안내나 표시가 빠진다. 예: 제외 목록의 "파일 없음"(#51 사소 1).
- **점검**: 옮기거나 바꾼 화면은 이전 동작 목록(문구, 정렬, 표시, 키)을 먼저 적고 하나씩 대조한다.

## 8. 값과 알고리즘이 두 곳에 있다

- 상한(예: 500)이 프런트에 하드코딩된다. 강조 알고리즘이 복사된다(#49 사소 5·6).
- 생성기가 계약 밖 순서나 이름에 기댄다(#46 F4).
- **점검**: 같은 값이나 규칙이 Python과 TypeScript 양쪽에 보이면 계약(브리지 타입 생성)으로 한 곳에서 넘긴다.

## 9. 실패 경로를 정리하지 않는다

- 예외가 나면 상태(스택, 연결, 잠금)가 남는다. `try/finally`가 없다(#53 m-1).
- 콜백 예외, HTTP 상태 코드, 무응답을 구분하지 않는다(#62 M-2·M-4).
- **점검**: 새 비동기 작업·외부 호출마다 실패, 취소, 시간 초과를 하나씩 일으켜 보고 상태가 원래대로 돌아오는지 확인한다.

## 10. 되돌릴 방법이 없다

- 편집 초안을 버릴 방법이 없거나, 적용하지 않은 값이 현재 값처럼 보인다(#51 중요 3).
- **점검**: 편집 화면마다 저장 전 상태, 취소, 기본값 복원이 구분되어 보이는지 확인한다.
