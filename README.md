# my-video-manager

Python + PySide6 + libmpv로 만든 Windows 개인 영상 라이브러리입니다.
감시 폴더의 하위 폴더까지 검사해 영상 제목과 썸네일을 표시하고 창 안에서 재생합니다.

## 환경 준비

Windows x64, **64비트 Python 3.10 이상**, **Node.js 22.12 이상**, `winget`, 인터넷 연결이 필요합니다.
저장소 루트의 PowerShell에서 실행합니다. Python 3.10.6으로 검증했습니다.
Node는 [공식 다운로드](https://nodejs.org/en/download)에서 22 LTS 이상을 설치하고
새 터미널의 `node --version`, `npm --version`으로 확인합니다.
이미 실행 중인 앱은 종료한 뒤 설치 스크립트를 실행하세요(DLL을 교체합니다).

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
```

스크립트는 `uv venv`로 worktree별 `.venv`를 만들고
`uv pip install --link-mode hardlink -e '.[dev,cuda]'`로 사용자 uv 캐시의 패키지를 하드링크합니다.
`uv`가 없으면 winget의 `astral-sh.uv` **0.8.15**(2025-09-03 출시)를 설치합니다.
이미 설치된 uv는 그대로 사용합니다. 캐시와 worktree가 다른 드라이브에 있는 등 하드링크가
불가능하면 uv가 경고를 출력하고 복사로 전환합니다. 하드링크된 `.venv` 패키지 파일을
직접 수정하지 마세요. 의존성 변경은 각 worktree에서 uv로 설치합니다. 이어서 `frontend/`에서
`npm ci`, lint, 타입 검사, 빌드를 실행합니다. PySide6 6.10.2에 WebEngine과 WebChannel이 포함돼 있습니다.
FFmpeg가 없으면 winget의 `Gyan.FFmpeg` **9.0.2**를 설치하며,
7-Zip이 없으면 `7zip.7zip` **26.04**를 설치합니다(관리자 권한 확인이 표시될 수 있습니다).
FFmpeg를 이미 별도로 설치했다면 `-SkipFFmpeg`를 붙일 수 있습니다.
winget 설치 후 기존 bash에서 `uv: command not found`가 나오면 IDE와 터미널을 다시 열어
사용자 PATH를 반영하세요. PowerShell의 `Get-Command uv`로 위치를 확인할 수 있습니다.
마지막으로 libmpv를 준비하고 FFmpeg·CUDA를 확인한 뒤 `pytest -n auto`로 테스트를 병렬 실행합니다.

이미 도구가 설치된 PC의 새 worktree에서는 빠른 모드를 사용합니다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1 -Worktree
```

빠른 모드는 전체 pytest, 프런트 lint·타입 검사, FFmpeg·7-Zip의 winget 설치를 건너뜁니다.
`npm ci`, `npm run build`, 브리지 타입 생성 검사(`--check`), WebEngine·FFmpeg·CUDA 확인은 유지합니다.
FFmpeg/ffprobe나 7-Zip이 없으면 전체 모드를 먼저 실행하라는 안내와 함께 실패합니다.
제출 전에는 별도로 전체 `pytest -n auto`와 프런트 lint·타입 검사를 실행하세요.
`-Worktree` 없이 실행하면 이 검사들을 모두 포함한 전체 준비 절차를 실행합니다.

libmpv는 [mpv 공식 설치 안내](https://mpv.io/installation/)에 연결된
[shinchiro Windows 빌드](https://github.com/shinchiro/mpv-winbuild-cmake/releases/tag/20261013)의
`mpv-dev-x86_64-20261013-git-9d144e57b6.7z`를 사용합니다.
`scripts/install_libmpv.py`에 고정 URL과 SHA-256이 있으며, 해시가 다르면 설치를 중단합니다.
검증한 압축 파일은 `%LOCALAPPDATA%\my-video-manager\cache\libmpv\`에 보관합니다.
재사용할 때도 SHA-256을 다시 검사하며 손상된 캐시는 버리고 다시 받습니다.
프로세스 간 잠금과 임시 파일의 원자 교체로 동시 준비 및 다운로드 중단을 처리합니다.
다른 프로세스가 캐시를 사용 중이면 30초마다 안내하며 잠금이 풀릴 때까지 기다립니다.
이전 준비 도구가 남긴 `.runtime/mpv-dev-*.7z`는 더 이상 사용하지 않으므로 직접 삭제해도 됩니다.
`.runtime/mpv/libmpv-2.dll`은 실행에 필요하므로 유지하세요.
캐시는 worktree를 삭제해도 남으며, 각 worktree의 DLL은 `.runtime/mpv/libmpv-2.dll`에만 둡니다. 아카이브의 BCJ2 필터 때문에 7-Zip이 필요합니다.
바이너리와 가상환경은 Git에서 제외합니다. 빌드 교체 시 URL과 SHA-256을 함께 갱신하세요.

`uv` 대신 `pip`만으로 수동 준비할 수도 있습니다(패키지를 복사하므로 디스크를 더 사용합니다):

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install --upgrade pip
.venv/Scripts/python -m pip install -e '.[dev,cuda]'
npm --prefix frontend ci
npm --prefix frontend run lint
npm --prefix frontend run typecheck
npm --prefix frontend run build
winget install --id Gyan.FFmpeg --version 9.0.2 --exact --source winget --accept-package-agreements --accept-source-agreements
winget install --id 7zip.7zip --version 26.04 --exact --source winget --accept-package-agreements --accept-source-agreements
.venv/Scripts/python scripts/install_libmpv.py
.venv/Scripts/python -m pytest -n auto
```

테스트는 각 작업자에서 `tests/conftest.py`가 `QT_QPA_PLATFORM=offscreen`과
`QTWEBENGINE_CHROMIUM_FLAGS=--disable-gpu`를 기본으로 적용하며, 사용자가 지정한 값은 유지합니다.
`-n auto`는 CPU 수에 맞춰 작업자를 만들고, 여러 작업이 같은 PC를 쓸 때는 `-n 2`처럼 수를 줄일 수 있습니다.
직렬 실행은 `-n auto`를 빼고 `.venv/Scripts/python -m pytest`로 실행합니다.
자식 프로세스 성공 경로의 대기 한도는 `tests/wait_helpers.py`의 `CHILD_READY_TIMEOUT`(기본 90초)이며 `MVM_TEST_CHILD_TIMEOUT` 환경 변수로 조정합니다. 조건이 충족되면 즉시 진행하고, 짧은 timeout 동작 검사는 별도 한도를 유지합니다.
건너뛴 테스트와 이유까지 비교하려면 직렬·병렬 명령에 각각 `-rs`를 붙입니다.

## 설치 파일 만들기

README의 환경 준비를 마친 뒤 빌드 extra와 [Inno Setup 6.5.4](https://jrsoftware.org/files/is6.5-whatsnew.htm)를 설치합니다.
Inno Setup 6.5.4는 2025-09-24 공개된 고정 버전입니다.
`ISCC.exe`를 PATH에 넣거나 `-InnoCompiler '설치 경로/ISCC.exe'`로 지정할 수 있습니다.

```powershell
uv pip install --python .venv/Scripts/python.exe --link-mode hardlink -e '.[build]'
winget install --id JRSoftware.InnoSetup --version 6.5.4 --exact --source winget --silent --accept-package-agreements --accept-source-agreements
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
```

`setup.ps1`이 만든 `.venv`에는 pip이 없어도 됩니다. 위 명령은 uv로 해당 환경에 빌드 도구를 추가합니다.
웹 빌드 → 생성 검사 → PyInstaller 6.16.0 onedir → Inno Setup 순서입니다.
버전은 `pyproject.toml`에서 읽고 `dist/installer/MyVideoManager-Setup-<version>.exe`로 만듭니다.
실행 폴더는 `dist/my-video-manager/`이며 웹·디자인 토큰·아이콘·Qt WebEngine 리소스와 로캘,
libmpv·FFmpeg·ffprobe를 포함합니다. CUDA·Whisper 모델은 넣지 않습니다.
`-Version 0.2.0`은 소스를 바꾸지 않고 설치 파일과 앱 표시 버전을 함께 지정합니다(Release DryRun용).
이미 만든 실행 폴더로 설치 파일만 다시 만들 때는 `-SkipPyInstaller -AppDirectory <실행 폴더>`를 사용합니다.

설치판 FFmpeg는 PATH와 무관하게 Gyan `9.0.2 essentials` 배포본을 사용합니다.
고정 URL·SHA-256은 `scripts/bundle_ffmpeg.py`에 있으며 `%LOCALAPPDATA%/my-video-manager/cache/ffmpeg/`의
공용 아카이브를 빌드마다 재검증합니다. `ffmpeg.exe`·`ffprobe.exe`만 추출하고 `source.json`에 출처와
실행 파일 해시를 기록합니다. `check_bundle.py`는 이 해시와 두 도구의 `-version`을 검사·출력합니다.
Qt는 웹 셸에 쓰지 않는 QML 트리와 debug 리소스를 제외하고 로캘은 ko·en-US만 포함합니다.
WebEngine이 참조하는 Qml·Quick 기반 DLL과 소프트웨어 렌더러는 유지합니다.
실행 파일은 콘솔 창을 만들지 않는 `windowed` 모드입니다. 받아쓰기·GPU 감지는 같은 exe의
`transcription` 하위 명령을 사용하며 부모가 연결한 stdout/stderr 파이프를 보존합니다.
설치 진입점은 이 자식 출력의 인코딩을 UTF-8로 지정해 한국어 JSON을 전달합니다.

새 `src/` 하위 프로세스 호출은 Windows에서 `CREATE_NO_WINDOW`를 사용해야 하며 정적 회귀 테스트로 검사합니다.
FFmpeg 원본 `LICENSE`·`README.txt`도 함께 추출합니다. 번들은 불필요한 Qt 모듈과 950,000,000 bytes 상한을 검사합니다.

## 설치해서 쓰기

제3자 라이선스·소스 안내는 설치 폴더의 `THIRD-PARTY-NOTICES.txt`, `ffmpeg/LICENSE.txt`, `ffmpeg/README.txt`, `licenses/`에 있습니다.

설치 위치는 사용자별 `%LOCALAPPDATA%/Programs/MyVideoManager`이고 관리자 권한을 요구하지 않습니다.
시작 메뉴 바로가기와 제거 프로그램을 등록하며 바탕화면 바로가기는 선택입니다.
Release에서 받은 설치 파일을 실행한 뒤 시작 메뉴의 **My Video Manager**로 엽니다.
코드 서명을 하지 않아 Windows SmartScreen 경고가 표시될 수 있습니다.
Python·Node·7-Zip은 설치판 실행에 필요하지 않습니다. 번역 CLI와 NVIDIA 드라이버는 사용자가 설치합니다.
동봉 FFmpeg·ffprobe는 실행 파일 옆 `ffmpeg/`, libmpv는 `mpv/`에서 찾습니다.
소스 실행의 PATH/WinGet FFmpeg와 `.runtime/mpv` 검색은 유지됩니다.
데이터 폴더(`~/.my-video-manager`, `--data-dir`)는 설치·제거 대상에 포함하지 않습니다.
업데이트·제거 전에는 트레이에서 **완전 종료**하세요. 새 판을 같은 위치에 덮어쓰거나
제거한 뒤 다시 설치해도 라이브러리·시청 기록·하이라이트·키 배치와 받은 모델은 남습니다.
설정의 **일반**에 현재 버전과 브라우저로 여는 GitHub Release 링크가 있습니다.

첫 자동 자막 요청 때 **자막 기능 준비**가 웹 화면 위에 나타납니다. GPU 확인 뒤 CUDA와
Whisper large-v3를 내려받고 검증합니다. 진행률·취소·다시 시도를 제공하며,
실패·취소하면 대기열을 보존하고 명시적으로 다시 시도할 때까지 기다립니다.
준비 중 앱 종료·강제 종료는 **중단됨**으로 안내하며, 다음 실행에서도 **다시 시도**를 기다립니다.
네트워크 무응답 중 취소는 최대 10초, GPU 탐지 취소는 약 0.1초 간격으로 확인합니다.
준비가 끝난 뒤 재설치해도 완료 파일을 재사용하며 다시 내려받지 않습니다.

첫 자막 요청 대화상자는 준비에 필요한 전체 다운로드 크기를 미리 알립니다(현재 약 4.3 GB).
준비 배너의 **파일 n/m · 전체 약 X GB**와 전체 진행률은 `runtime_assets.py`의 고정 크기에서 계산합니다.
진행률은 재사용 파일을 포함한 전체 바이트 기준이며, 검증·압축 풀기가 끝날 때까지 최대 99%로 표시합니다.
실패·취소 결과는 데이터 폴더의 `subtitle-preparation.json`에 남으므로 앱을 다시 시작해도
**다시 시도**를 누르기 전에는 다운로드를 시작하지 않습니다. 대기 중인 받아쓰기 항목이 없으면
실패 배너를 숨기고 다시 시도도 실행하지 않으며, 새 항목을 요청하면 이전 결과와 다시 시도를 표시합니다.
오류 상세는 배너에 짧게 표시하고, 데이터 폴더의 `logs/subtitle-preparation.log`에 남깁니다
(UTF-8, 파일당 256 KiB, 이전 로그 2개). URL 쿼리·토큰은 가리고 홈 경로는 `~`로 줄입니다.
이 로그는 백업에 포함하지 않으며 로그 기록 실패는 준비 흐름을 중단하지 않습니다.

앱 시작·백업·복원 등 일반 진단은 데이터 폴더의 `logs/app.log`에 남깁니다.
준비 로그와 같은 UTF-8·파일당 256 KiB·이전 로그 2개·민감 정보 가림 규칙을 쓰며,
백업에서 제외하고 쓰기 실패는 무시합니다. 준비 로그는 준비 실패와 재시도 이력을
별도로 찾을 수 있도록 기존 경로를 유지합니다.

### 자막 기능 준비 API

작업자 스레드에서
`AppCore.prepare_subtitle_support(cancellation=Event(), progress=callback)`을 호출하면
CUDA와 Whisper large-v3를 같은 흐름에서 준비합니다.
독립 어댑터 `SubtitlePreparation(data_directory, adapter=RuntimeDownloadAdapter(), gpu_available=...)`도
사용할 수 있으며 `prepare()`가 CUDA 디렉터리들과 모델 경로를 반환합니다.
콜백은 `PreparationProgress(phase, asset, completed, total)`을 받습니다.
download/verify/extract는 파일별 바이트, reuse/ready는 완료 개수, probe는 GPU 확인입니다.
추가 필드 `file_index`, `file_count`, `overall_completed`, `overall_total`은 전체 파일 순서와
누적 바이트 진행률입니다. `AppCore.subtitle_support_status()`는 이전 결과와 완료 manifest만 읽습니다.
취소 토큰은 청크마다 검사하며 네트워크 무응답 제한 시간은 10초입니다.
**진행률 콜백은 예외를 던지지 않아야 합니다.** 화면 갱신 실패 등 콜백 내부의 오류는 호출자가 처리합니다.

`PreparationError.kind`는 `gpu_unavailable`, `network`, `hash_mismatch`, `disk_full`,
`cancelled`, `invalid_archive`, `storage`, `preparation_required`를 구별하고 한국어 안내와 별도 `detail`을 제공합니다.
NVIDIA 드라이버는 사용자가 설치해야 합니다.
다운로드·해시 검증·추출과 공간 검사는 어댑터에서 주입할 수 있습니다.
GPU 감지는 최대 15초의 별도 Python 자식(`transcription --probe-cuda`)에서 실행하므로 앱 프로세스에
`ctranslate2`를 올리지 않습니다. 설치판은 같은 실행 파일의 `transcription --probe-cuda`를 사용합니다.
frozen 받아쓰기 자식은 `prepared()`로 완료 결과만 읽고, 없으면 `preparation_required`로 바로 실패합니다.
준비 다운로드는 명시적인 `prepare_subtitle_support()` 흐름에서만 실행합니다.

CUDA 버전은 기존 `cuda` extra와 같고 Windows x64 공식 PyPI 휠 URL·SHA-256은
`runtime_assets.py`에 고정했습니다. Whisper도 같은 파일의 revision과 SHA-256으로 검증합니다.
CUDA는 `data_directory/runtime/cuda/<wheel-sha256>/`에 DLL만,
모델은 기존 `data_directory/models/` 아래 `large-v3/<revision>/`에 둡니다.
소스 실행의 `models/models--Systran--faster-whisper-large-v3/snapshots/<revision>/`가 있으면
고정 파일 전체의 크기와 SHA-256을 한 번 확인해 `ready.json`을 만들고 그 경로를 그대로 재사용합니다.
맞지 않는 HF 캐시는 보존하고 앱 전용 폴더에 다시 받습니다.
반쯤 받은 `.part`와 추출 중 `.partial` 폴더는 다음 시도에서 지웁니다.
HF 캐시를 재사용할 때도 현재 revision의 앱 전용 `.partial`은 먼저 정리합니다.
이전 버전의 완료 런타임·모델은 실행 중인 DLL과 구버전으로 되돌리기를 보호하기 위해 자동 삭제하지 않습니다.
고정 버전을 바꾼 뒤 새 판 받아쓰기까지 확인했다면, 모든 앱을 완전히 종료하고
`runtime/cuda/<이전 wheel-sha256>`와 `models/large-v3/<이전 revision>` 및 이전 `.partial`만 수동으로 지울 수 있습니다.
현재 해시·revision은 `runtime_assets.py`가 원본입니다. 공유 Hugging Face 캐시는 자동으로 정리하지 않습니다.
완료 표시와 파일 크기가 맞으면 다시 받지 않으며, 같은 데이터 폴더의 준비 작업은 프로세스 사이에서도 직렬화합니다.
소스 받아쓰기는 기존 `.venv` CUDA와 Hugging Face 모델 캐시를 계속 사용합니다.

공식 CUDA 휠 실측(2026-10-15): cuBLAS 567,544,208바이트 / DLL 788,719,104바이트,
cuDNN 684,630,375바이트 / DLL 1,007,375,176바이트입니다.
모델 파일과 다운로드·추출 중 임시 공간은 별도로 필요합니다.

## 새 버전 올리기

`scripts/release.ps1`은 로컬 릴리스용입니다. Git for Windows, GitHub CLI의 `gh auth login`,
README의 "설치 파일 만들기"에 있는 빌드 extra 설치까지 먼저 마쳐야 합니다.
`release.ps1`은 의존성을 설치하지 않고 `build.ps1`을 호출합니다. `main`에서만 실행하며 작업 트리가 깨끗하고 `main`,
`origin/main`, 실제 원격 main이 모두 같아야 합니다. 기존 로컬/원격 태그나 GitHub Release가 있으면 멈춥니다.

```powershell
# 검사와 계획 출력만: 버전·커밋·태그·원격·원격 추적 ref를 바꾸지 않음
powershell -ExecutionPolicy Bypass -File scripts/release.ps1 -Version 0.2.0 -DryRun
# 위 동작에 빌드 추가: pyproject.toml 수정 없이 -Version을 build.ps1에 전달
powershell -ExecutionPolicy Bypass -File scripts/release.ps1 -Version 0.2.0 -DryRun -Build
# 실제 릴리스
powershell -ExecutionPolicy Bypass -File scripts/release.ps1 -Version 0.2.0
```

실제 실행은 `pyproject.toml` 버전을 올려 한국어로 커밋하고 설치 파일을 빌드합니다.
설치 파일의 SHA-256 파일을 만든 뒤 `v<version>` 태그와 main을 atomic push하고,
`gh release create --verify-tag`로 설치 파일과 체크섬을 함께 게시합니다.
노트는 현재 main에 포함된 가장 높은 버전 태그 이후의 커밋 제목입니다(태그가 없으면 전체).
설치 파일은 `dist/installer/MyVideoManager-Setup-<version>.exe`, 체크섬은 그 옆의 `.exe.sha256`입니다.
기존 태그·Release를 덮어쓰거나 강제 push하지 않습니다.
빌드 실패나 원격에서 거부한 push는 로컬 버전 커밋과 이번에 만든 태그를 자동 복구합니다.
다른 파일 변경이나 불확실한 원격 상태가 있으면 보존하고 복구 명령을 안내합니다.
push 뒤 Release 생성이 실패하면 원격 main과 태그를 유지하며 Release 확인·생성·자산 추가 명령을 안내합니다.
자동 재발행하지 않으므로 안내에 따라 상태를 확인하세요.
Ctrl+C로 빌드를 중단하면 PowerShell이 실패 복구 catch를 건너뛸 수 있습니다.
`git status`와 `git log --oneline`으로 확인하고, 보존할 작업을 저장한 뒤 이번 버전 커밋만
`git revert <버전 커밋>`으로 되돌리세요. 다른 작업 이후의 HEAD를 시작 커밋으로 reset하지 마세요.
`-DryRun -Build`의 빌드 산출물은 Git에서 제외된 폴더에 남으며 tracked 파일과 커밋은 그대로입니다.

## 외부 자막 (#66)

영상 등록·다시 검사 때 각 위치의 폴더에서 영상 이름(확장자 제외)으로 시작하는
`.srt`, `.vtt`, `.smi`를 가져옵니다. 복사본이 여러 폴더에 있으면 모두 확인합니다.
영상 이름 뒤는 비어 있거나 `.`, `_`, `-`, 공백, `[`, `(`로 시작해야 하며,
같은 폴더의 여러 등록 영상에 맞으면 가장 긴 영상 이름에만 연결합니다.
파일 이름의 `ko`·`kor`·`korean`, `en`·`eng`·`english` 등으로 언어를 읽으며,
SMI의 언어 클래스와 `lang` 선언도 구별합니다. 알 수 없는 언어는 `None`(언어 모름)입니다.
현재 위치가 사라지거나 다른 내용의 영상으로 교체되면 다음 검사에서 이전 외부 자막 연결도 지웁니다.

인코딩 판정은 **BOM(UTF-8, UTF-16 LE/BE) → NUL 패턴으로 판별한 BOM 없는 UTF-16 →
UTF-8 → CP949 → EUC-KR** 순서이며, 엄격한 디코딩을 사용합니다. EUC-KR의 일반적인
문자는 CP949에도 포함되므로 이 경우 기록되는 인코딩 이름은 `cp949`입니다.
SRT·VTT의 큐 설정과 태그는 검색 글자에서 빼고, SMI의 빈 싱크는 앞 큐의 끝 시각으로 씁니다.
SMI 마지막 큐의 끝은 영상 길이이며, 길이를 모르면 시작+5초를 씁니다.
다음 싱크는 같은 언어 클래스 기준이고, P가 없는 빈 싱크는 모든 클래스를 닫습니다.
잘못된 블록은 건너뛰고 개수를 경고에 남기며, 읽힌 줄이 하나도 없을 때 파일 실패로 처리합니다.

`AppCore.external_subtitles(video_id)`는 파일 경로·인코딩·경고와 언어별 자막 줄을 반환합니다.
파일 크기·수정 시각이 같으면 다시 읽지 않으며, 실패한 파일은 다음 검사에서 재시도합니다.
바뀐 파일의 읽기 실패는 이전 검색 줄을 제거하고 경고로 남깁니다. 자막 파일 삭제도 검색에 반영합니다.
일부 블록만 실패한 파일은 읽힌 줄과 경고를 함께 보관하고, 서명이 같으면 다시 읽지 않습니다.
파일별 저장·삭제를 커밋하므로 검사 중단 뒤 다음 검사에서 나머지 파일을 이어서 맞춥니다.
검색 결과의 출처는 `external`(외부 자막)이고 `video_id`, `start`, 선택적 `language`를 제공합니다.
원어·번역 자막, 검수·번역 대기열에는 영향을 주지 않습니다. 기존 DB 버전도 유지합니다.
영상 상세의 정보 탭에서 파일 목록·언어별 줄 수·읽기 경고를 확인할 수 있고,
웹 검색에서는 외부 자막 출처와 언어 칩을 표시합니다. 상세 조회는
`external_subtitle_summaries(video_id)`로 자막 본문 없이 집계만 가져옵니다.

### 위치·파일 없음·제외

**감시 폴더 추가**로 여러 폴더를 등록하고 **감시 폴더 해제**로 선택한 폴더를 해제합니다.
해제하면 그 폴더 아래 위치를 모두 제거하며, 다른 위치가 없는 영상은 **파일 없음**으로 남습니다.
직접 추가했던 위치도 해당 폴더 아래라면 해제됩니다. 다른 감시 폴더와 겹치는 위치는 다음 검사에서 다시 발견됩니다.
실제 파일과 영상의 시청·하이라이트·원어 자막·태그·사용자 지정 시리즈 기록은 지우지 않습니다.

**파일 직접 추가**로 감시 폴더 밖 파일도 등록할 수 있습니다. 직접 추가한 위치도 **다시 검사**할 때
변경·사라짐을 확인합니다. 추가가 0건이면 최소 길이 미만·제외 목록·비영상(GIF 포함)·이미 등록됨 중
해당 이유를 안내합니다. 이름 변경·이동 후 같은 내용이 발견되면 기존 영상에 새 위치가 붙고,
복사본은 영상 하나의 여러 위치로 표시됩니다. 모든 위치가 사라지면 파일 없음이 되며 재생·자막 요청에
다시 검사하거나 연결하라는 안내가 나옵니다. 감시 폴더 밖으로 옮긴 영상은 **파일 다시 연결**을 누릅니다.
원래 영상과 지문이 다르면 연결을 거절합니다. 자동 시리즈는 새 파일 이름·폴더로 다시 계산하지만,
파일 없음 영상의 기존 시리즈 소속과 사용자가 편집한 구성·순서는 보존합니다.
다시 연결하거나 감시 폴더를 해제해도 남은 위치를 기준으로 자동 시리즈를 즉시 다시 계산합니다.

**제외**는 지문 기준으로 기억하므로 이름을 바꾸거나 복사해도 검사에서 목록에 다시 나타나지 않습니다.
**제외 목록 → 선택 영상 되돌리기**로 기록과 함께 복원합니다. 실제 파일은 삭제하지 않습니다.
**제목 변경**은 표시 제목만 바꾸며 파일 이름은 바꾸지 않습니다.

최소 길이는 기본 **60초**입니다. **최소 길이 설정**에서 초 단위로 바꾸며 0이면 길이 제한을 없앱니다.
변경 후 다시 검사하면 새 기준을 적용하며, 이미 등록한 영상은 기준을 높여도 유지합니다.
새 GIF는 길이·확장자와 관계없이 등록하지 않습니다. 이전 버전에서 이미 등록한 GIF는 DB 이전 때
기록과 위치를 유지한 채 제외 목록으로 옮깁니다. 사용자가 되돌린 GIF는 이후 검사·이름 변경·이동에도
기존 영상으로 유지하며 다시 자동 제외하지 않습니다. 설정은 공용 `Settings` 저장소의
`library.min_duration_seconds` 키에 저장해 다음 실행에도 유지합니다.

목록에는 **다 봄**, **보다 만 (N%)** 상태가 표시됩니다. 분류는 한 번의 시청에서 실제로 재생한
구간의 합집합으로 계산합니다. 건너뛴 구간은 제외하고, 반복해서 본 구간은 한 번만 셉니다.
배속과 무관하게 영상 시간 기준으로 90% 이상이면 다 봄, 5% 이상 90% 미만이면 보다 만,
5% 미만이면 틀어보기입니다. 서로 다른 시청의 구간을 합쳐 다 봄으로 만들지는 않습니다.
다 본 시청이 2회 이상이면 **즐겨 보는 영상**도 표시합니다.

보다 만의 N%는 **마지막 정지 위치 / 영상 길이**입니다. 실제 재생한 비율과는 다를 수 있습니다.
이후 틀어보기로 끝나도 보다 만 상태는 유지되고, 마지막 정지 위치는 갱신됩니다.
보다 만 영상을 다시 열면 그 위치의 3초 전(최소 0초)부터, 다 본 영상은 처음부터 재생합니다.
진행 중인 시청은 기본 5초마다 저장하며, 정상 종료 때는 즉시 저장합니다.
비정상 종료 후에는 마지막 저장분까지 복구하고 해당 시청을 닫습니다(저장 이후의 진행분은 유실될 수 있습니다).

| 키 | 재생 화면의 동작 |
|---|---|
| Enter | 재생 / 일시정지 |
| ← / → | 5초 뒤로 / 앞으로 |
| , | 3초 뒤로 |
| ↑ / ↓ | 속도 +0.25 / -0.25 |
| Insert | 현재 순간에 지점 하이라이트 |
| Delete | 구간 하이라이트 시작 / 끝 |
| Home / End | 이전 / 다음 하이라이트의 시작으로 이동 |
| ; | 재생 화면의 하이라이트 패널 접기 / 펴기 |
| / | 자막 켜기 / 끄기 |
| PgUp / PgDn | 이전 / 다음 영상 (시리즈 안에서는 이전 / 다음 화) |
| . | 원어 자막 / 번역 자막 전환 (번역이 없으면 안내) |

열린 구간은 재생 종료·영상 전환 시 그 위치에서 닫으며, 끝이 시작 이하이면 시작 위치의 지점 하이라이트로 저장합니다.
Delete로 직접 끝낼 때도 같은 규칙을 적용합니다. Home은 현재 위치에서 1초를 뺀 시각보다 앞의 시작점을,
End는 현재 위치 뒤의 시작점을 찾으며, 해당 항목이 없으면 이동하지 않습니다.

진행 막대는 노란 선으로 지점, 초록 범위로 구간, 주황 범위로 아직 열린 구간을 표시합니다.
재생 화면 오른쪽 하이라이트 패널에는 현재 영상에 남긴 하이라이트의 시각과 메모가 표시됩니다. 클릭하거나 Tab으로
목록에 들어가 ↑↓로 선택한 뒤 Enter를 누르면 그 시각으로 이동합니다. 긴 메모는 줄임표로
표시하고 마우스를 올리면 전체 내용을 볼 수 있습니다. 노란 선은 현재 위치와 가장 가까운
항목을 표시하며, 구간 안이면 거리를 0으로 셉니다. 동률이면 시각순 첫 항목을 표시합니다.
영상이 바뀌면 선택을 비우고 이어볼 위치의 가까운 항목을 한 번 보여 줍니다. 같은 영상의 추가·삭제는 남아 있는
선택과 스크롤을 보존합니다. 최근 3초 동안 목록을 스크롤하거나 선택하지 않았다면,
가까운 항목이 바뀔 때와 숨겼던 패널을 다시 펼칠 때 그 항목이 보이도록 따라갑니다. 스크롤 손잡이를 잡고 있거나
목록을 조작하는 동안에는 따라가지 않으며 선택한 항목은 자동으로 바꾸지 않습니다.
`;` 또는 위쪽 **하이라이트 패널 접기 / 펴기**로 패널을 전환합니다. 기본 키는 오른손 홈 열의
미사용 키이며 키 배치에서 바꿀 수 있습니다. 전체 화면에서는 패널이 숨겨지고, 창으로
돌아오면 접기 상태를 복원합니다. 모아보기 중 목록 항목을 누르면 기존 복습 기록을
보존하고 해당 시각부터 일반 시청을 시작합니다.

**하이라이트 목록 · 시각·메모 편집**에서 현재 영상의 하이라이트를 고르고 메모와 시작·끝 시각(초)을
편집하거나 삭제할 수 있습니다. 목록 항목에서 Enter를 누르면 시각·메모 편집을 엽니다.
구간 체크를 해제하면 지점으로 바뀝니다.
시각은 0 이상 영상 길이 이하이며 구간의 끝은 시작보다 뒤여야 합니다.
메모는 하이라이트에 속하고 하이라이트 삭제 시 함께 없어집니다. 편집 대화상자에서는 재생 키 배치가 작동하지 않습니다.

라이브러리의 **선택한 영상 태그**, 하이라이트 목록의 **태그 편집**에서 태그를 달고 뗍니다.
이름을 입력하고 Enter를 한 번 누르면 입력한 이름을 추가합니다. 기존 후보를 쓰려면 ↓/↑로
고른 뒤 Enter를 한 번 누릅니다. 후보를 고르지 않은 `강의` 입력은 `강의 노트`로 바뀌지 않습니다.
후보 팝업에서는 PgUp/PgDn으로 한 화면씩, Home/End로 처음·끝 후보로 이동합니다.
Esc로 팝업을 닫은 뒤 ↓로 다시 열 수 있습니다. 빈 입력에서 Enter는 무시합니다.
Tab으로 입력칸·목록·버튼 사이를 이동하고 Space로 버튼을 누를 수 있으며, Esc로 닫습니다.
변경은 즉시 저장됩니다. **선택한 태그 떼기**는 현재 영상 또는 하이라이트의 연결만 없앱니다.
**모든 태그 관리**에서 이름을 바꾸거나 삭제하면 모든 영상·하이라이트에 반영됩니다.
라이브러리의 **태그 필터**는 영상 자체에 붙은 태그로 거릅니다. **모든 영상**으로 필터를 해제합니다.
하이라이트 태그는 영상에 자동으로 붙지 않습니다.

태그 표시 이름은 Unicode NFC 정규화 후 앞뒤 공백을 없애고 연속 공백을 한 칸으로 바꿉니다.
폭 없는 문자 등 서식 문자(`Cf`)와 제어 문자(`Cc`, 탭·개행 포함)는 제거합니다.
정리한 표시 이름이 비어 있거나 50자를 넘으면 거부합니다. 길이는 NFC 정규화 후의 문자 수입니다.
중복 판정과 자동 완성에는 NFKC와 `casefold()`를 적용해 호환 문자와 대소문자를 구별하지 않습니다.
처음 만든 표시 이름은 유지되어 `①강`, `Brand™`, 전각 문자 등도 그대로 보입니다.
이름 변경이 다른 태그와 충돌하면 합치지 않고 거부합니다.
같은 태그의 대소문자 표기 변경은 가능합니다. 태그는 계층 없이 영상·하이라이트가 공유합니다.

목록에서는 방향키와 Enter가 선택·열기로 동작합니다. 키 배치는 앱 창이 활성화된 동안만 처리하며,
mpv 자체 키 바인딩은 끕니다. 검사 중에도 창을 트레이로 숨길 수 있습니다. 완전 종료는 검사를 마친 뒤 가능합니다.
**번역 방식 / 재시도**에서는 방식·모델·추론 강도와 OpenCode Go 키·이어받기를 설정합니다.

### 키 배치 설정

**설정(Ctrl+7 / Alt+S) → 키 배치**를 엽니다. 재생 중 Alt+S 메뉴의 **키 배치…**도 같은 설정 탭으로 이동합니다.
명령을 방향키로 고른 뒤 Enter 또는 **키 바꾸기**를 누르고 새 키를 누르세요.
문자·숫자·방향키·기능키와 Ctrl/Alt/Shift 조합을 지원합니다. 숫자 패드 Enter도 Enter로 처리합니다.
키 캡처 중 Esc는 취소하며, Esc 자체는 목록 복귀·취소 전용이라 할당할 수 없습니다.
Alt+S와 Ctrl+1~Ctrl+7은 설정 메뉴·페이지 이동 예약 키이므로 재생 명령에 할당할 수 없습니다.
Tab으로 버튼 사이를 이동하고 Space로 실행할 수 있습니다.

**적용** 또는 **저장 후 닫기**를 누르면 즉시 반영되고 다음 실행에도 유지됩니다.
서로 다른 명령에 같은 키를 지정하면 두 명령을 알려주고 저장하지 않습니다.
두 명령의 키를 서로 바꾼 다음 한 번에 저장할 수도 있습니다.
**선택 명령 기본값** 또는 **전체 기본값**으로 되돌린 뒤 적용하세요.
개별 복원 키를 다른 명령이 쓰고 있으면 해당 명령도 바꾸거나 전체 기본값을 사용합니다.
**취소**·Esc로 닫으면 아직 적용하지 않은 변경만 버립니다.

키 설정은 재생 명령에 적용되며 목록 탐색과 편집 대화상자의 기본 키 동작은 유지됩니다.
이전/다음 하이라이트와 이전/다음 영상 명령의 화면별 의미도 유지됩니다.
재생 화면 아래 안내에는 현재 설정한 키가 표시됩니다.
코어의 `key_bindings()`는 명령·한국어 이름·현재 키·기본 키를 반환하고,
`save_key_bindings()`는 명령별 키 목록 전체를 검사해 저장합니다.
`reset_key_bindings(command)` 또는 인자 없는 호출로 개별·전체 복원을 합니다.
`set_key_bindings()`는 기존 키 배치 교체 API이며 이제 변경을 저장합니다.
생성자의 `key_bindings` 주입은 해당 인스턴스에만 적용됩니다.
저장에는 공용 `Settings`의 `keys.bindings`를 사용하고 기본값과 다른 명령만 기록합니다.
후속 기능의 새 기본 키가 기존 사용자 키와 겹치면 사용자 설정을 유지하고 새 명령은 미할당으로 표시합니다.


### 웹 폴더 관리·설정 (#51)

**폴더 관리(Ctrl+6)**와 **설정(Ctrl+7 / Alt+S)**을 웹으로 엽니다.
폴더 관리에는 감시 폴더 추가·해제·다시 검사·파일 직접 추가, 제외 목록·관심 없음 되돌리기,
최소 영상 길이와 검사 안내가 있습니다. 폴더·파일 선택에는 Windows 기본 대화상자를 사용합니다.
검사 중에는 폴더·파일 추가, 해제, 다시 검사, 제외 복원과 최소 길이 변경을 잠급니다.
관심 없음 복원과 모든 태그 관리는 기존과 같이 사용할 수 있습니다.

설정의 왼쪽 분류는 **일반 / 키 배치 / 번역 / 받아쓰기**입니다.

- 일반: 최소 길이(폴더 관리와 같은 값), 위험 작업으로 표시한 완전 종료와 확인·취소.
- 키 배치: 명령별 키 캡처, 저장 전 충돌 안내, 개별·전체 기본값, 적용. 변경한 키는 재생·F1 안내·빈 모아보기 안내에 바로 반영됩니다. 캡처 중에는 Ctrl+1~7·Alt+S·F1이 페이지를 옮기지 않으며 Esc는 캡처만 취소합니다. 적용 전 변경은 분류·페이지 이동 중 유지되며, 현재 키와 별도 초안으로 표시합니다. 미적용 건수를 확인하고 변경 취소로 초안을 모두 버릴 수 있습니다.
- 번역: 현재 방식·모델·추론 강도·키 상태·이어받기 설정과 실패·보류 건수, 선택·재시도 대화상자 진입.
- 받아쓰기: 영상별 원어 지정과 자동 규칙 안내, 자막 대기열로 이동. 새 모델·GPU 설정은 추가하지 않습니다.

웹 셸에서 Alt+S는 설정 탭으로 이동합니다. 재생 중에는 전체 화면에서도 기존 설정 메뉴를 열고, 닫으면 같은 재생 세션으로 돌아갑니다.

### 하이라이트 모아보기와 복습

라이브러리의 **하이라이트 모아보기**에서 모든 영상의 하이라이트를 한 목록으로 봅니다.
**하이라이트 태그**로 거르고 **처음부터 차례 재생** 또는 항목 더블클릭/Enter로 재생합니다.
필터는 하이라이트에 직접 붙인 태그만 사용합니다. 정렬은 영상 제목 자연 정렬(대소문자 구분, `2강`이 `10강`보다 먼저) →
영상 ID → 시작 시각 → 하이라이트 ID 순입니다. 같은 제목의 서로 다른 영상은 각각 묶입니다.
파일 없음(위치가 없는 영상)은 목록에 **재생 불가**로 표시하며 차례 재생에서 건너뜁니다.
제외 영상의 하이라이트는 시리즈와 같은 정책으로 목록에서 숨기고 재생에서도 건너뜁니다.
하이라이트·복습 기록은 보존되며, 제외를 되돌리면 다음 목록 갱신이나 새 모아보기 시작 때 다시 나타납니다.

지점은 기본 10초, 구간은 시작부터 끝까지 재생하며 영상 끝을 넘지 않습니다.
영상 끝에 찍은 길이 0인 지점은 차례 재생에서 건너뜁니다. 파일 없음이나 길이 0인 항목을 직접 고르면
재생할 수 없다는 안내를 띄웁니다. 끝나면 다음 하이라이트로 자동 이동하며,
필요하면 영상도 바뀝니다. 마지막 항목이 끝나거나 마지막 항목에서 End를 누르면 모아보기 목록으로 돌아옵니다.
자동 이동·반복 때도 배속과 자막 표시 설정은 유지됩니다. 같은 영상 안에서는 플레이어를 유지하고
시작점으로 탐색하며, 다른 영상으로 이동할 때만 파일을 새로 엽니다.
반복 상태는 Home/End·PgUp/PgDn으로 수동 이동해도 유지되며, `\`로 끄거나 모아보기를 나갈 때 해제됩니다.
`.`로 고른 원어/번역 자막도 같은 영상의 항목 이동·반복에서는 유지합니다.
다른 영상으로 이동하거나 모아보기를 새로 시작하면 원어 자막으로 시작합니다.

| 키 | 모아보기 재생 중 동작 |
|---|---|
| Home / End | 목록의 이전 / 다음 하이라이트 (Home은 첫 항목에서 유지) |
| `\` (백슬래시) | 현재 지점 또는 구간 반복 켜기 / 끄기 (화면에 상태 표시) |
| PgDn | 다음 영상의 첫 하이라이트 (마지막 영상에서 유지) |
| PgUp | 현재 영상의 첫 하이라이트, 이미 첫 항목이면 이전 영상의 첫 하이라이트 |
| Insert / Delete | 지점 생성 / 구간 시작·끝 (새 항목은 다음 목록 갱신·재생 시작 때 반영) |
| Esc / 목록으로 | 재생을 끝내고 모아보기 목록으로 복귀 (목록에서 Esc는 라이브러리로) |

Enter, ←/→, `,`, ↑/↓, `/`는 일반 재생과 같습니다. Home/End와 PgUp/PgDn의 화면별 의미는
앱 코어에서 결정합니다. 모아보기에서 나가기 전까지 일반 시청으로 전환하지 않습니다.
재생 순서와 하이라이트의 시각은 시작할 때 고정하고, 항목 이동 때 삭제·파일 없음·제외는 다시 확인해 건너뜁니다.
PgUp/PgDn도 파일 없음·제외 영상을 양방향으로 건너뛰며, 현재 영상이 뒤늦게 이 상태가 되어도 이동 기준점은 유지합니다.
열린 구간은 항목 전환·종료 시 닫습니다. 생성·편집 결과는 **목록 갱신** 또는 목록 재진입 때 확인합니다.

복습은 해당 항목에서 실제 재생한 구간의 합집합이 **영상 시간 기준 3초 이상**이거나,
3초보다 짧은 항목을 **전체 재생**했을 때 즉시 기록합니다. 탐색으로 건너뛴 부분, 일시정지 시간,
중복해서 재생한 부분은 더하지 않습니다. 배속을 바꿔도 영상 시간으로 계산하며, 끝으로 건너뛰기만 해서는
복습이 되지 않습니다. 마지막 복습 시각은 한 번의 항목 재생에서 기준을 처음 충족한 시각입니다.
반복·다시 열기로 새로 재생하면 다시 갱신하며, 항목을 지우면 그 항목의 복습 기록도 지웁니다.
모아보기는 `record_viewing=False`로 시작하므로 시청 기록·다 봄/보다 만·이어볼 위치가 바뀌지 않습니다.

코어의 `AppCore(reel_settings=ReelSettings(point_duration=10, minimum_played=3))`로
기본 길이와 기록 기준을 설정할 수 있습니다(`ReelSettings`는 `reel.py`). 설정 화면은 후속 범위입니다.
`reel_entries(tag_id=None)`는 하이라이트·영상 제목·길이·재생 가능 여부·마지막 복습 시각을 반환합니다.
`start_reel(tag_id=None, highlight_id=None)`로 시작하고 `reel_playback`에서 현재 항목과 재생 범위를,
`reel_repeat`에서 반복 상태를 읽습니다. `ReelPlayback.action`은 첫 시작·영상 전환의 `open` 또는
같은 영상의 항목 이동·반복의 `seek`입니다. 재생 위치는 기존 `core.playback.report()`로 보고하고,
그 호출이 끝난 직후 `advance_reel_if_due()`를 호출해 다음 재생 지시를 반영합니다.
모든 리스너가 이전 위치를 받은 뒤 전환하므로 구독 순서에 의존하지 않습니다.
엔진 EOF는 `advance_reel_if_due(eof=True)`로 전달합니다. 영상 끝에 걸친 항목은 엔진과 DB의 길이가
조금 달라도 끝 도달로 처리합니다. 탐색 직후 첫 위치 보고는 `seeked=True`로 전달합니다.
`last_highlight_revisited_at(highlight_id)`와 `last_video_revisited_at(video_id)`는 마지막 복습 시각을
반환하며, 기록이 없으면 `None`입니다. 영상별 값은 남아 있는 하이라이트들의 가장 최근 복습 시각입니다.
후속 숨겨진 보석(#14)은 영상별 API를 사용할 수 있습니다.

### 숨겨진 보석

라이브러리 첫 화면 위쪽에 최대 **10개**를 이유와 함께 표시합니다. 추천 카드에서 ←/→로 고른 뒤
Enter를 누르거나 카드를 한 번 클릭하면 바로 재생합니다. 보다 만 영상은 기존 이어보기 규칙에 따라
마지막 정지 위치의 3초 전부터 재생합니다. Tab/Shift+Tab으로 카드 목록과 버튼, 라이브러리 사이를 이동합니다.
**선택 영상 관심 없음** 버튼 또는 카드 목록에 포커스가 있을 때만 동작하는 **Backspace**로 추천에서
영구히 뺍니다. 마우스로는 원하는 카드를 **우클릭 → 관심 없음**으로 바로 뺄 수 있으며 재생되지 않습니다.
이 지역 키는 재생 키 배치와 별개이며 재생 화면에서는 추천을 변경하지 않습니다.
**관심 없음 되돌리기**에서 영상을 고르고 Enter 또는 되돌리기 버튼을 누르면 다시 추천 대상이 됩니다.
관심 없음은 라이브러리 표시·파일·시청 기록에 영향을 주지 않으며 재실행 후에도 유지됩니다.
재생에서 돌아오면 출발했던 추천 카드 또는 라이브러리 목록에 포커스를 돌려줍니다.
추천 계산에 오류가 생겨도 라이브러리는 사용할 수 있으며 추천 영역에만 오류를 안내합니다.

선정 우선순위와 같은 기준 안의 순서는 다음과 같습니다. 한 영상에는 가장 앞선 이유 하나만 표시합니다.

1. **보다 만**: 마지막 시청이 최근인 순. 이유의 %는 이어볼 위치 / 영상 길이입니다.
2. **복습할 때가 됨**: 하이라이트가 있고 마지막 복습과 가장 최근 하이라이트 생성 중 더 최근 시각부터
   30일 이상 지난 영상. 그 기준 시각이 오래된 순입니다.
3. **태그가 비슷함**: 즐겨 보는 영상의 영상 태그와 하나 이상 겹치며 시청이 없는 영상.
   겹친 태그 수가 많은 순, 같으면 등록이 오래된 순이며 이유에 태그 이름을 표시합니다.
   제외한 즐겨 보는 영상의 태그는 근거에서 빼고, 파일 없음·관심 없음 영상의 태그는 계속 근거로 씁니다.
4. **오래 시청 없음**: 등록 후 30일 이상 시청이 없는 영상. 등록이 오래된 순입니다.

추천에서 **틀어보기만 있는 영상은 시청 없음**으로 봅니다. 하이라이트 모아보기 역시 일반 시청이 아닙니다.
기간 경계는 두 기준 모두 정확히 **30일째부터 포함**합니다(29일 제외, 30·31일 포함).
공용 `core.settings.set("recommend.unwatched_days", 30)`와
`core.settings.set("recommend.revisit_days", 30)`으로 각각 기간을 바꿀 수 있습니다.
값은 0 이상 365000 이하의 유한한 일수이며 소수도 허용합니다. 설정 화면은 제공하지 않습니다.

시리즈의 보다 만·태그가 비슷함·오래 시청 없음은 순서상 **아직 다 보지 않은 가장 앞 화 하나**만 후보입니다.
파일 없음·제외 화는 건너뜁니다. 첫 미완료 화가 관심 없음이거나 일반 추천 기준에 걸리지 않으면 다음 화를 대신 고르지 않습니다.
**하이라이트 복습은 예외**로 다 본 화도 후보가 되며, 같은 시리즈에서는 복습 기준 시각이 가장 오래된 한 편만 남깁니다.
가장 오래 밀린 화가 파일 없음·제외·관심 없음이면 그다음으로 오래 밀린 화가 대상이 됩니다.
관심 없음은 그 영상 하나에 대한 결정이므로 첫 미완료 화가 관심 없음이어도 같은 시리즈의 다른 화는 복습 후보가 될 수 있습니다.
따라서 한 시리즈에서 첫 미완료 화와 복습 한 편이 최대 두 개 나올 수 있습니다. 같은 영상이면 앞선 기준 하나로만 나오고,
이처럼 같은 영상이 두 기준에 겹칠 때는 복습 자리를 다른 화로 채우지 않습니다.
모든 기준에서 파일 없음·제외·관심 없음은 추천하지 않습니다.
같은 정렬 값은 영상 ID 순으로 고정하며 전체 상한은 여전히 10개입니다.
추천은 목록 갱신과 재생에서 라이브러리로 돌아올 때 다시 계산하므로 다 본 영상과 변경된 태그·시리즈가 반영됩니다.

이전 버전은 하이라이트 생성 시각을 저장하지 않았으므로 기존 하이라이트는 최초 업그레이드 시각부터
기간을 계산합니다. 이후 생성 시각은 별도 테이블에 저장하고, 시각·메모 편집은 생성 시각을 바꾸지 않습니다.
하이라이트를 삭제하면 그 생성·복습 시각도 제거합니다. 기존 테이블 구조와 DB 버전은 바꾸지 않습니다.

공개 코어 API: `hidden_gems()`는 영상·기준·이유·겹친 태그를 반환하며,
`dismiss_video(video_id)`, `dismissed_videos()`, `restore_dismissed_video(video_id)`로 관심 없음을 관리합니다.
`viewing_status_map()`과 `video_tags_map()`은 제외·시청 없음·태그 없음까지 포함한 영상 ID별 전체 상태를
일괄 조회합니다. `library_snapshot()`은 영상·시청 상태·태그·시리즈를 한 번씩 조회한 결과를 반환하고,
목록과 `hidden_gems(snapshot=...)`가 같은 결과를 공유합니다. 태그 필터는 목록에만 적용하고 추천은 전체 영상을 기준으로 합니다.
썸네일 아이콘은 경로와 파일 수정 시각으로 캐시하여 반복 갱신 비용을 줄이며 파일이 바뀌면 다시 읽습니다.

### 시청 통계 코어

`AppCore.viewing_statistics(days, *, tz=None)`는 오늘을 포함한 최근 7·30·90·365일의
`ViewingStatistics`를 반환합니다. 기본은 시스템 로컬 시간대이며, 테스트에서는 `tz`에
`datetime.tzinfo`를 주입합니다. 시청을 시작한 날짜에 실제 재생 구간의 합집합을 세며,
틀어보기·모아보기 복습은 빼고 저장 전 진행 중인 시청도 포함합니다.
일별 시간·횟수(빈 날은 0), 이전 같은 기간 대비 증감, 최장 연속 일수, 상위 영상 5개와
전체 기간의 라이브러리 현황을 제공합니다. 이전 값이 0이면 증감률은 `None`이며 화면에서는
"이전 기록 없음"으로 표시합니다. 상위 영상은 시청 시간·횟수 내림차순, 제목 오름차순이고
제외·파일 없음 상태를 함께 반환합니다. 라이브러리 현황과 새 영상 수는 제외 영상만 뺍니다.

`AppCore.video_viewing_statistics()`는 영상 ID별 `VideoViewingStatistics`를 일괄 조회합니다.
시청 횟수·시간은 전체 기간이고, 마지막 시청은 틀어보기를 포함한 `updated_at` 최댓값입니다.
제외·파일 없음·시청 없는 영상도 반환하며, 영상 수와 무관하게 SELECT 2회로 조회합니다.
`library_snapshot().video_statistics`에도 같은 ID별 수치가 들어 있습니다. 스냅샷은
시청 상태와 수치를 한 번의 시청 조회·순회로 함께 계산하므로 카드에서 별도 API를 다시 부를 필요가 없습니다.
저장 시 이미 병합한 구간은 그대로 합산하고, 행과 진행 중 시청을 확보한 뒤 읽기 트랜잭션을
닫고 파싱합니다. 기간 통계는 SELECT 5회이며 필요한 날짜의 로컬 자정 경계를 한 번 만들고
시작 시각을 `bisect`로 찾습니다. 범위에서 이틀 이상 먼 ISO 날짜는 시간대 변환 없이 건너뜁니다.
반환 dataclass의 시간 단위는 초, 날짜·시각은 ISO 문자열이며
`dataclasses.asdict()` 후 JSON으로 직렬화할 수 있습니다. 순수 계산은 `statistics.py`의
`viewing_statistics(viewings, videos, days, today, tz, settings)`와
`video_viewing_statistics(viewings, video_ids, settings)`에 있습니다.

### 원어 자막

목록에서 영상을 고르거나 재생 중 **자막 만들기 / 원어 지정**을 누릅니다.
**자동 감지** 또는 언어 코드(`ko`, `en`, `ja`, `zh` 등)를 고르면 자막 대기열에 들어갑니다.
같은 요청을 반복해도 중복 등록하지 않으며, 먼저 들어온 순서대로 한 영상씩 처리합니다.
원어를 바꿔 다시 요청하면 새 요청으로 교체합니다. 완료된 자막을 다시 만들 때는 기존 줄이
교체된다는 확인을 받습니다. 실패하면 기존 자막을 유지하며, 같은 버튼으로 재시도합니다.

받아쓰기는 별도 작업자와 낮은 우선순위의 별도 프로세스에서 실행되어 화면·재생 중에도 진행됩니다.
완료 즉시 재생 중인 영상에 원어 자막이 붙고 `/`로 표시를 바꿀 수 있습니다.
원어와 줄 수, 실패 이유는 창 아래 상태 표시줄에 표시됩니다.
받아쓰기 중 **완전 종료**를 선택하면 **지금 종료 / 취소**를 묻습니다. **지금 종료**는 받아쓰기
프로세스를 중단하며, 해당 항목은 다음 실행에서 처음부터 다시 처리합니다.
**취소**는 종료 요청만 취소합니다. 종료 도중 시청 저장 등에 실패해도 대기열 처리를 재개합니다.
Windows Job 객체가 받아쓰기 자식·손자 프로세스를 묶으므로 앱 강제 종료 때도 함께 종료됩니다.

### 자동 자막 규칙과 대기열

**자막 대기열(Ctrl+4)** 또는 트레이 메뉴의 **대기열 보기**에서 상태·진행률과 **자동 자막 규칙**을 열 수 있습니다.
규칙은 감시 폴더 또는 영상 태그 하나와 선택적인 원어 코드로 저장합니다.
폴더 규칙은 해당 폴더 아래에서 지문 기준으로 처음 등록되는 영상에만 적용합니다.
기존 영상의 이름 변경·이동·복사·파일 없음에서 복귀에는 적용하지 않으며,
다른 폴더에서 규칙 폴더로 옮겨도 다시 넣지 않습니다.
태그 규칙은 방금 새로 붙인 영상 태그의 규칙만 적용합니다. 이미 붙어 있는 태그를 다시 입력하거나
관련 없는 태그를 붙여도 요청하지 않습니다. 태그를 뗀 뒤 다시 붙이는 것은 새 부착으로 봅니다.
이미 원어 자막이 있거나 대기열에 있는 영상은 다시 자동 요청하지 않습니다.
규칙을 저장할 때는 자막이 없고 대기 중이 아닌 기존 영상 수를 보여 주고 함께 넣을지 묻습니다.
**아니요**를 고르면 기존 영상을 재검사하는 것만으로는 대기열에 넣지 않습니다.
폴더 규칙끼리 겹치면 먼저 만든 규칙의 원어를 사용합니다. 태그 부착 시에는 폴더 규칙을 적용하지 않습니다.
파일 없음·제외 영상은 자동 대상에서 뺍니다.
규칙을 해제해도 이미 들어간 항목은 남으며 **빼기**로 제거할 수 있습니다.

순서는 **직접 요청 > 자동 대상**, 같은 등급에서는 최초 요청 순서입니다.
같은 원어의 자동 요청을 직접 요청하면 기존 순서를 보존하면서 직접 요청 등급으로 올립니다.
원어 변경·실패 재시도·완료된 번역의 직접 재요청은 새 직접 요청이며 이전 순번과 앞당기기를 지웁니다.
순서 정보가 없는 이전 버전 항목은 직접 요청 등급의 마지막에서 기존 상대 순서를 유지합니다.
**앞당기기**는 등급보다 우선해 다음 처리의 맨 앞에
놓으며, 여러 번 앞당기면 마지막에 앞당긴 영상이 가장 앞섭니다. 실행 중인 받아쓰기나 번역 묶음은
중단하지 않습니다. 받아쓰기와 번역은 각각 한 작업자에서 이 순서를 따르며 함께 실행할 수 있습니다.

영상 하나당 **대기 / 받아쓰는 중 / 번역 중 / 보류 / 완료 / 실패** 중 하나를 표시합니다.
완료 항목은 **이번 앱 실행에서 완료된 영상만** 표시합니다. 대기·진행·보류·실패 항목은 재실행 후에도 표시합니다.
알림이 나온 뒤에도 이번 실행의 완료 항목은 남지만 앱을 다시 열면 과거 완료 내역은 표시하지 않습니다.
대기열 창을 숨기거나 닫으면 화면 갱신 타이머도 멈춥니다.
받아쓰기를 다시 요청한 영상은 새 받아쓰기 상태를 우선 표시합니다.
받아쓰기 진행률은 하위 프로세스가 임시 진행 파일로 보고하는 처리 오디오 시간 / 영상 길이입니다.
보고는 파일을 원자적으로 교체하며, 보고 파일 쓰기·교체 오류는 받아쓰기 결과에 영향을 주지 않습니다.
모델 다운로드·음성 읽기 중에는 0%, 저장 직전까지 최대 99%이며 완료하면 100%입니다.
번역 진행률은 저장한 줄 / 대상 줄입니다. 단계가 바뀌면 그 단계의 진행률로 표시합니다.
시작 시 남아 있던 `transcribing`·`translating`은 `queued`로 복구합니다.

**빼기**는 진행 중인 어댑터에 취소를 전달하고 결과를 버립니다. 저장된 원어·번역 자막은 보존하며,
같은 원어 자막의 번역은 재실행해도 자동으로 다시 넣지 않습니다. 완료 항목도 화면에서 뺄 수 있습니다.
원어 자막을 새로 생성하거나 명시적으로 번역을 요청하면 다시 처리할 수 있습니다.
**실패 항목 모두 재시도**는 받아쓰기·번역 실패 모두를 대상으로 하며 번역의 저장한 묶음은 유지합니다.
파일 없음 등으로 재시도할 수 없는 항목은 건너뛰고 나머지를 계속 처리하며, 건너뛴 수와 이유를 화면에 알립니다.
보류는 별도 버튼으로 재시도할 수 있으며 CLI 계정의 한도 대기 시간은 유지합니다.
보류 번역을 처리하다 취소하면 기존 보류 상태와 재시도 시각을 유지합니다.
방향키로 영상을 선택하고 Tab/Shift+Tab으로 버튼 이동, Space로 실행, Esc로 창을 닫습니다.

### 트레이와 중복 실행

창의 X는 재생을 멈추고 시청 기록을 닫은 뒤 트레이로 숨깁니다. 자막 대기열은 계속 처리합니다.
처음 숨길 때만 **트레이에서 계속 처리합니다**를 알립니다.
트레이 메뉴는 **열기 / 대기열 보기 / 완전 종료**이며 **설정(Ctrl+7)**에도 **완전 종료**가 있습니다.
재생 중 **대기열 보기**를 누르면 **Ctrl+4**와 같이 재생을 정리하고 자막 대기열 페이지로 이동합니다.
대기·처리·보류 항목이 모두 사라지면 이번 처리의 영상별 완료·실패 개수를 한 번 알립니다.
실패 항목은 화면에 남아도 처리 종료로 집계하고, 번역이 남은 영상은 최종 번역 결과로 집계합니다.
Windows의 알림 설정이나 방해 금지 모드에 따라 알림이 화면에 보이지 않을 수 있습니다.

같은 데이터 폴더는 하나의 앱만 실행합니다. 두 번째 실행은 기존 창을 앞으로 가져오고 종료합니다.
데이터 폴더별 `QLockFile`과 `QLocalServer`를 사용하며, 서로 다른 `--data-dir`은 독립 실행됩니다.

영상 옆에 이미 있는 자막은 mpv 기본 동작대로 자동으로 불러옵니다.
앱이 만든 원어 자막이 있으면 추가 트랙으로 붙여 우선 선택하며, 다시 생성할 때도 앱의 트랙만
교체합니다. `/`는 현재 선택된 자막 표시를 켜고 끕니다. 기존 자막 파일은 수정하지 않습니다.
실패는 GPU 사용 불가·음성 디코드 실패·모델 다운로드 실패·기타로 구분해 짧게 표시하며,
상태 표시줄 위에 포인터를 두면 상세 오류를 볼 수 있습니다.
원어를 직접 지정하지 않았고 자막 줄이 없거나 감지 확률이 50% 미만이면 **알 수 없음**으로 저장합니다.
코어의 `Transcript.spoken_language`는 이때 `None`이고 `translation_eligible`은 `False`이므로
후속 번역 기능에서도 알 수 없는 원어를 번역 대상으로 취급하지 않습니다.

Windows GPU 검증 조합은 **faster-whisper 1.2.1, CTranslate2 4.8.3,
CUDA 12.8 cuBLAS 12.8.4.1, cuDNN 9.8.0.87**입니다.
`setup.ps1`은 NVIDIA 공식 Windows wheel을 **이 저장소의 `.venv`에만** 설치하며,
시스템 CUDA Toolkit이나 PyTorch 설치는 필요하지 않습니다. 앱이 해당 DLL 경로를 프로세스 안에 등록합니다.
RTX 5070(Blackwell)에서 NVIDIA 드라이버 **610.47**, Python **3.10.6**으로
`large-v3` FP16 실제 음성 받아쓰기를 확인했습니다. 드라이버는 스크립트가 변경하지 않습니다.
Blackwell에는 CUDA 12.8 이상이 필요하므로 오래된 cuBLAS/cuDNN을 섞지 마세요.
근거: [faster-whisper GPU 요구사항](https://github.com/SYSTRAN/faster-whisper#gpu),
[CTranslate2 Windows 빌드](https://github.com/OpenNMT/CTranslate2/blob/v4.8.3/python/tools/prepare_build_environment_windows.sh),
[NVIDIA cuDNN 지원표](https://docs.nvidia.com/deeplearning/cudnn/backend/v9.8.0/reference/support-matrix.html).

GPU가 없거나 드라이버·DLL 초기화에 실패하면 **명확한 오류와 함께 해당 요청을 실패 처리**하며
CPU로 자동 전환하지 않습니다. 다른 요청의 처리는 계속하며 라이브러리와 재생은 사용할 수 있습니다.
설치 스크립트의 CUDA 확인이 실패해도 설치된 앱의 라이브러리·재생 기능은 실행할 수 있습니다.
첫 자막 요청은 Hugging Face에서 `large-v3` 모델(약 3 GB)을 데이터 폴더의 `models/`에 내려받습니다.
모델은 Git에 넣지 않으며, 기본 데이터 폴더는 저장소 밖 사용자 프로필 아래에 있습니다.
첫 실행에는 인터넷과 모델 저장 공간이 필요합니다. 이후에는 캐시를 재사용합니다.

### 번역 자막

원어 자막이 완성되면 한국어 번역이 자동으로 이어집니다. 한국어·알 수 없는 원어·빈 자막은
번역하지 않습니다. 번역은 GPU를 사용하지 않으므로 다른 영상의 받아쓰기와 함께 진행되며,
같은 영상의 원어 자막을 다시 만드는 동안에는 기다립니다. 번역 완료 전에도 원어 자막을 볼 수 있습니다.

**번역 방식 / 재시도**에서 Codex(CLI, 기본), Claude(CLI), OpenCode Go(API)를 고릅니다.
Codex·Claude는 별도로 설치하고 구독 계정으로 로그인해야 하며 CLI는 `PATH`에서 찾습니다.
OpenCode Go는 데이터 폴더의 `secrets/opencode-go.dpapi`에 Windows 사용자 범위로 암호화한 키를 사용합니다.
세 방식 모두 자막 텍스트를 외부 서버로 전송하고 **구독 사용량 한도를 공유**합니다.
키 입력·교체·삭제와 설정 변경은 확인할 때 저장하며, 취소하면 초안을 버립니다.
키 확인은 사용자가 요청할 때만 유료 기본 모델에 최대 출력 1토큰 요청을 보냅니다. 모델 목록 조회 성공은 키 확인이 아닙니다.

미설정 모델은 Codex `gpt-5.6-terra`, Claude `claude-sonnet-5-5`, OpenCode Go `deepseek-v4.1-flash`입니다.
Codex·Claude의 별도 **기본(CLI 기본값)** 선택은 모델 인자를 생략합니다. 추론 강도의 **기본(모델 기본값)**도 인자를 생략합니다.
모델과 강도는 `translation.model.<방식>`, `translation.effort.<방식>`에 각각 저장하며, 모든 방식에서 모델 이름을 직접 입력할 수 있습니다.
OpenCode Go의 강도 지원은 아직 실제 키로 확인하지 못했으므로 선택지를 숨기고 인자를 보내지 않습니다.
모델·강도를 CLI가 거부하면 **모델을 쓸 수 없음** 실패로 안내하며 한도 보류와 구분합니다.

**실패하면 OpenCode Go로 이어서**는 키가 있으면 기본으로 켭니다. Codex·Claude의 한도·오류·형식 재시도 소진 뒤
남은 줄만 Go로 번역하고, 작업의 나머지 묶음과 재시작 뒤에도 이어받기를 유지합니다. 직접 취소는 이어받지 않습니다.
줄마다 실제 방식을 기록해 검수 화면에 표시하며, 이전 버전의 출처 없는 줄은 추측하지 않습니다.
Go도 한도에 걸리면 보류하고 서버가 알려준 재시도 시각을 따릅니다. 시각이 없으면 기존 15분 대기를 사용합니다.
학습 사용·정책 미확인·무보존 계약 만료 경고를 모델 옆에 표시합니다. DeepSeek 계약 만료일은 2026-10-31이며 자동 갱신하지 않습니다.
실제 키의 인증·번역 품질과 사용 조건은 [ADR-0005](docs/adr/0005-opencode-go-subscription-translation.md)를 참고하세요.

아래 CLI 보류·실패 규칙은 이어받기를 사용할 수 없는 경우에 적용합니다.

한 번에 Codex·Claude는 기본 **120줄**, OpenCode Go는 **100줄**을 한국어로 번역합니다.
기본값은 `translation_models.py`의 방식별 정책에 있으며, 테스트는 `AppCore(translation_batch_size=...)`로
크기를 지정할 수 있습니다. 각 묶음과 한 줄 재번역에는 바로 앞 **10줄**을 읽기 전용 맥락으로 붙입니다.
떨어진 여러 줄은 각 대상 앞 10줄을 합치고 중복·대상 줄을 뺍니다. 총 100줄까지 가까운 앞 줄부터 모읍니다.
번역된 맥락 줄은 원문과 번역을, 미번역 줄은 원문만 보내며 맥락 ID가 응답에 섞이면 형식 오류입니다.
용어집은 작업 안에서 누적하며 먼저 정한 번역을 유지합니다. 최대 **200항목**이고 새 응답에 다시 나온
항목과 성공한 대상 원문에서 대소문자 그대로 단어 경계가 일치한 항목을 최근 사용으로 셉니다.
원문·번역은 각각 60자까지이며 줄바꿈 항목은 버립니다. 프롬프트 용어집은 UTF-8 JSON 24KiB까지 최근 항목을 남깁니다. 잘못된 항목만 버리고 번역은 받습니다.
용어집은 성공한 묶음의 진행과 같은 트랜잭션으로 저장합니다. 보류·실패 뒤 재시도·앱 재시작에도
이어지고 작업이 끝나거나 삭제되면 함께 정리됩니다. 원어 전체 재생성은 새 작업으로 시작합니다.
줄 ID·개수·중복·빈 텍스트를 검증하며 형식 오류는 즉시 묶음을 반으로 줄여 다시 시도합니다.
최소 **10줄**(남은 대상이나 명시적 테스트 크기가 더 작으면 그 크기)에서 최대 **3회** 실패한 뒤에만
형식 오류 재시도 소진으로 판정하고 기존 실패·이어받기 규칙을 적용합니다. 줄인 상태로 **3번 연속 성공**하면
두 배씩 해당 방식 기본값까지 복구합니다. 줄인 크기는 그 작업·방식 안에서만 유지하며 저장하지 않습니다.
계속 형식 오류가 나면 CLI는 `120 → 60 → 30 → 15 → 10 × 3`, Go는 `100 → 50 → 25 → 12 → 10 × 3`으로 최대 7회 호출합니다.
OpenCode Go 전송 계층의 형식 오류(예: JSON 본문이 객체가 아님)는 묶음을 줄이지 않고 최대 3회 재시도합니다.
모델 응답 내용의 형식 오류에만 줄이기를 적용합니다. 한도·연결 오류는 묶음을 줄이지 않습니다. 구독 사용량 한도는 **보류**로
저장하며 **해당 CLI의 모든 영상 번역을 15분간 쉬고** 자동 재시도합니다. CLI별 재시도 시각은
앱을 다시 켜거나 원어 자막을 재생성해도 유지됩니다. **번역 방식 / 재시도**에서 확인하면 실패·보류한
작업을 저장한 묶음부터 다시 요청하지만, 같은 CLI의 한도 대기 시간은 건너뛰지 않습니다.
다른 CLI를 선택하면 다음 묶음부터 그 CLI의 한도 상태에 따라 진행합니다. 로그인 계정을 앱에서
구분하지 않으므로 같은 CLI에서 계정을 바꿔도 기존 대기 시간은 유지됩니다.
대기 시간이 끝나면 보류 작업보다 `queued` 작업을 먼저 처리하며 각 그룹 안에서는 요청 순서를 따릅니다.
같은 작업·CLI에서 한도 오류가 **3회 연속** 발생하면 해당 작업을 실패로 바꾸고 자동 재시도를 멈춥니다.
이 횟수는 앱 재시작 후에도 유지하고, 해당 CLI로 묶음을 성공시키거나 직접 재시도를 요청하면 초기화합니다.
세 번째 오류가 발생했을 때도 CLI 전체의 마지막 15분 대기는 유지합니다. 한도를 확인한 뒤 직접 재시도하세요.
인증 오류·CLI 없음은 해소 시각을 알 수 없어 자동 재시도 없이 해당 작업을 **실패**로 둡니다.
로그인·설치 후 직접 재시도하세요. 이 오류와 형식·시간 초과 등 다른 실패는 나머지 영상을 막지 않습니다.

완료한 묶음은 즉시 DB에 저장하므로 정상 종료·강제 종료 후에도 남은 묶음부터 이어갑니다.
전체 번역이 준비된 시점에만 재생용 결과를 원자적으로 교체합니다. 다시 번역하다 실패하면
기존 번역을 유지합니다. 원어 자막을 재생성하면 기존 번역과 진행 기록은 지워지고 새 줄 ID로 번역합니다.
`AppCore.request_translation(video_id, line_ids=[...])`로 지정한 원어 줄만 다시 번역할 수도 있습니다.
검수한 번역 줄은 자동 재번역과 직접 재시도에서 보존합니다.

재생은 원어 자막으로 시작하고 **`.`**로 원어와 번역을 바꿉니다. 번역이 아직 없으면 기존 선택을
유지하고 안내합니다. `/`의 표시 켜기·끄기는 언어 전환과 별개입니다. 앱 자막을 제거하면 남아 있는
기존 자막 트랙의 첫 항목을 직접 선택합니다. 영상 옆 자막 파일은 수정하지 않습니다.

`codex exec`는 비대화식 읽기 전용 sandbox와 승인 금지로 실행합니다. `--ignore-user-config`로
사용자 `config.toml`, `--ignore-rules`로 사용자·프로젝트 실행 규칙을 제외하고, `--disable hooks`로
사용자·프로젝트 훅을 끕니다. `-c project_doc_max_bytes=0`으로 작업 경로의 프로젝트 AGENTS도 제외합니다.
다만 **전역 `$CODEX_HOME/AGENTS.md` 또는 `AGENTS.override.md`가 있으면 그 지시는 번역 호출에도
적용**됩니다(Codex 0.162.1 기준). `hooks.json`의 사용자 정의 세션·도구 훅은 번역 호출에서 비활성화합니다.
인증은 기존 `CODEX_HOME`을 그대로 사용합니다. 빈 임시 홈은 기존 로그인을 읽지 못하며,
인증 파일 복사는 키링 로그인과 호환되지 않고 토큰 갱신 상태도 갈라지므로 사용하지 않습니다.
전역 지시만 별도로 끄면서 인증 저장소를 유지하는 지원 옵션은 확인하지 못했습니다.
따라서 전역 지시가 번역 결과에 영향을 줄 수 있습니다. 읽기 전용 sandbox는 **모델이 실행하는 명령의
파일 쓰기와 네트워크 접근**을 막지만, 파일 읽기는 허용하며 CLI 자체의 인증·모델 통신과 상태 저장까지
막는 완전한 격리는 아닙니다. 참고: [AGENTS 탐색](https://learn.chatgpt.com/docs/agent-configuration/agents-md),
[훅](https://learn.chatgpt.com/docs/hooks), [인증 저장소 구현](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/login/src/auth/storage.rs).

`claude -p`는 safe mode에서 모든 도구를 끕니다. 여러 줄인 번역 지시문은 임시 파일을
`--system-prompt-file`로 전달하므로 Windows `.cmd`·`.bat` 런처에서도 잘리지 않습니다.
자막 안의 지시 문구는 데이터로 번역합니다. 작업 폴더는 데이터 폴더 아래 `translation-temp/`의
임시 폴더이며 실행 후 정리합니다(강제 종료 때 남은 임시 폴더는 삭제해도 됩니다).
Windows Job으로 CLI 자식·손자 프로세스를 묶어 앱 종료 시 함께 종료합니다.

원어 자막은 DB에 시작·끝 시각과 텍스트, 줄별 UUID로 저장합니다.
줄 ID는 다시 읽기·앱 재시작에도 유지되며, 전체 재생성에서는 새 세대와 새 줄 ID로 교체합니다.
향후 번역·검수는 이 ID를 참조할 수 있습니다. mpv 전달용 `.srt` 캐시는 데이터 폴더의
`playback-subtitles/`에만 만들고 영상 옆에는 쓰지 않습니다. 이 캐시는 삭제해도 다시 만들어집니다.

### 검색

라이브러리의 **검색**에서 제목·모든 위치의 파일 이름·영상과 하이라이트의 태그·메모·원어와 번역 자막을
한꺼번에 찾습니다. 결과에는 영상 제목, 일치한 범위와 원문이 나오며 메모·자막에는 장면 시각도 나옵니다.
검색 칸에서 **↓** 또는 Enter로 결과 목록에 이동하고, 방향키로 선택한 뒤 **Enter** 또는 클릭으로 재생합니다.
메모·자막은 표시한 장면부터, 제목·파일 이름·태그는 기존 이어보기 규칙으로 재생합니다.
파일이 없는 영상도 기록을 검색할 수 있으며 결과에 **파일 없음**이 표시됩니다.
해당 결과를 선택하면 검색 창에 위치를 다시 연결하라는 짧은 안내를 표시합니다.
전체 결과는 최대 **500개**입니다. 더 있으면 **결과가 많습니다. 더 길게 입력하세요**라고 안내합니다.
제목 → 파일 이름 → 태그 → 메모 → 자막 순으로 수집하며, 잘린 경우 검색어를 구체화하세요.
상한 안에 든 자막 결과는 영상 ID·장면 시각순으로 표시하므로 줄 수정·재번역 후에도 순서가 유지됩니다.

띄어쓰기와 대소문자, Unicode 표현 차이는 무시하는 부분 일치입니다.
예를 들어 `체중 이동`으로 `체중이동을`을 찾고 `WORLD`로 `World`를 찾습니다.
따옴표·`%`·`_`는 검색 연산자가 아닌 글자 그대로 찾습니다. 빈 검색어는 결과를 표시하지 않습니다.
자막은 SQLite FTS5 trigram 색인을 사용하며, 1~2글자는 색인에 저장된 내용 전체에서 부분 문자열로
찾으므로 긴 검색어보다 느릴 수 있습니다. [SQLite FTS5 trigram 문서](https://sqlite.org/fts5.html#the_trigram_tokenizer).
기존 원어·번역 자막은 창을 먼저 표시한 뒤 백그라운드에서 각각 색인합니다.
준비 중에는 검색 창에 **검색 색인 준비 중…**을 표시하고, 완료되면 입력한 검색어의 결과를 보여줍니다.
미정규화 줄이 1만 개 이상이면 정규화 후 FTS5 `rebuild`를 한 번 실행하며,
소량 변경은 행별로 갱신합니다. 원문은 저장 트리거로 반영하고 정규화 값은 색인 준비 또는 검색 직전에
앱 코어가 채웁니다. `prepare_search()`와 `search_index_ready`로 준비와 상태를 조회할 수 있고,
화면 없이 `search()`를 직접 호출해도 필요한 준비를 수행합니다. 트리거는 SQLite 내장 기능만 사용하므로
앱 전용 함수를 등록하지 않은 구 빌드나 외부 도구에서도 저장·수정·삭제할 수 있습니다.
줄 수정·구간 교체(#9)를 포함한 모든 쓰기 경로에 트리거가 적용되므로 별도 색인 갱신 호출이 필요 없습니다.
장면 시각은 색인에 복사하지 않고 검색할 때 원어 자막 줄에서 읽으므로 번역 결과도 최신 시각을 표시합니다.
제목·파일 이름·태그·메모는 검색할 때 현재 값을 읽습니다.
`AppCore.search(query)`는 `SearchResponse(results, truncated)`를 반환하며,
각 결과는 원어(`transcript`)와 번역(`translation`) 출처, 일치한 원문, 장면 시각과 파일 없음 상태를 포함합니다.

### 시리즈

검사할 때 **같은 폴더 + 같은 제목 틀**의 번호 붙은 영상이 시리즈로 묶입니다.
`드라마A 1화`·`드라마A 2화`와 `드라마B 1화`·`드라마B 2화`는 서로 다른 시리즈입니다.
번호는 `01강`, `1화`, `3회`, `제1강`·`제1화`·`제1회`, `E01`, `EP 01`, `Episode 1`,
`Lecture 1`, `S01E02`, `Part 3` 같은 명시 표기를 우선합니다.
명시적인 표기가 없으면 해상도·코덱, 연도로 보이는 4자리 숫자, 6자리 방영일, 8자리 16진수 CRC,
대괄호·괄호 안 그룹명 등의 꼬리표를 빼고 공백·구분자로 분리된 1~3자리 숫자 하나를 번호로 봅니다.
제목 틀은 **번호 표기 앞부분만** Unicode NFKC, 대소문자, 공백·구분자로 정규화한 것입니다.
번호 뒤의 부제·방영일·팬섭 꼬리표는 키에 넣지 않고, 앞부분의 기술·그룹명 꼬리표도 뺍니다.
따라서 `파이썬 1강 - 변수`와 `파이썬 2강 - 함수`가 묶이며, `01. 소개`·`02. 설치`처럼
빈 제목 틀도 같은 폴더 안에서 묶입니다. 다만 빈 제목 틀에 명시적인 회차 표기 없이 맨 번호만 있으면
0 또는 1부터 시작하고 중간에 빠진 번호가 1개 이하일 때만 묶습니다.
`1 소개`·`3 설치`는 묶지만 `1`·`5`, `12 Angry Men`·`21 Jump Street`는 묶지 않습니다.
`강`·`화`·`E`·`Lecture`·주차 등 명시 표기가 있으면 이 연속 번호 제한을 적용하지 않습니다.
`01 회의 녹화`·`02 가족 여행`이나 `Top 5 goals`·`Top 10 goals`도 묶일 수 있어
필요하면 편집으로 바로잡습니다. 표시 이름은 번호가 가장 앞선 기준 영상의 번호 앞 원문을 쓰고
대괄호 그룹명과 양 끝 구분자를 빼고 대소문자는 유지합니다. 제목 틀이 비어 있으면 폴더 이름을 씁니다.

`1주차 1강`·`1주차 2강`·`2주차 1강`에서는 주차를 시즌처럼 보고 주차·강 번호로 정렬합니다.
시즌·주차 표기가 없으면 시즌 1로 봅니다. 0번은 빈 제목 틀의 맨 번호에서만 허용하고, 번호 없음,
`Show.S01E01E02` 같은 다중 화 표기나 번호가 여러 개여서 모호한 이름은 제외합니다. 같은 제목 틀 안에서 번호가 겹치면
해당 번호의 영상들을 모두 빼며, 유효 영상이 2개 이상일 때만 새 시리즈를 만듭니다.
복사본이 있는 영상은 전체 위치 경로를 대소문자 무시 사전순으로 정렬한 첫 위치를 사용합니다.
그 위치의 폴더와 이름만 자동 묶기에 쓰며 한 영상은 한 시리즈에만 들어갑니다.

목록의 **시리즈 편집**에서 시리즈를 고르거나 새로 만들고, 영상 넣기·빼기·위로·아래로 이동 후
저장합니다. 다른 시리즈의 영상은 원래 시리즈에서 먼저 빼야 합니다. 저장 전 취소는 변경을 남기지 않습니다.
파일 없음 영상은 시리즈 표시·편집 화면에 **파일 없음**으로 보이며 소속을 유지합니다.
제외 영상은 시리즈 표시·편집에서 보이지 않지만 소속을 유지하고, 편집해서 저장해도 숨겨진 구성원을
기존 순번에 남깁니다(보이는 영상을 빼서 순번이 끝을 넘으면 끝에 둡니다). 되돌리면 그 자리로 복귀합니다.
사용자가 넣거나 뺀 영상과 정한 순서는 재검사·재실행 후에도 보존됩니다.
이름 변경·넣기·빼기와 기존 영상의 상대 순서 변경은 따로 기록합니다.
순서를 바꾸지 않았다면 새 화는 번호상 앞 화 뒤에, 앞 화가 없으면 바로 뒤 화 앞에 넣습니다.
순서를 바꾼 적이 있다면 새 화는 번호상 가장 가까운 앞 화 뒤에 넣으며, 앞 화가 없으면 끝에 넣습니다.
사용자가 모든 영상을 빼도 시리즈는 남고, 이미 뺀 영상을 다시 넣지 않습니다.

PgUp/PgDn은 시리즈 순서를 우선합니다. 시리즈 밖에서는 재생을 시작할 때 보던 목록의 순서를 쓰며,
두 경우 모두 파일 없음·제외 영상을 건너뛰고 다음 재생 가능한 영상이 없으면 현재 영상을 유지합니다.
시리즈 끝에서 일반 목록으로 넘어가거나 처음으로 순환하지 않습니다.
영상 전환은 코어의 `switch_to(video_id)`에서 기존 시청과 열린 하이라이트 구간을 닫고
기존 이어보기 규칙으로 시작 위치를 구해 새 시청을 시작합니다.

기본 저장 위치는 `%USERPROFILE%/.my-video-manager/library.sqlite3`이며,
썸네일은 같은 폴더의 `thumbnails/`에 저장합니다. 원본 영상에는 쓰지 않습니다.
DB에는 썸네일을 데이터 폴더 기준 상대 이름으로 저장하므로 데이터 폴더 전체를 옮겨도 표시됩니다.
별도 데이터로 실행하려면 다음 명령을 사용합니다.

```powershell
.venv/Scripts/python -m my_video_manager --data-dir .local/demo-data
```

### 웹 모아보기·검색 검증

영상 상세의 정보 탭에는 외부 자막 파일 이름, 언어별 줄 수와 읽기 경고가 나옵니다.
파일이 없으면 짧은 안내를 표시하고, 일부 블록만 읽힌 파일은 줄 수와 경고를 함께 표시합니다.
긴 파일 이름은 말줄임하며 마우스를 올리면 전체 이름을 확인할 수 있습니다.
검색의 외부 자막 결과에는 출처와 언어 칩(확인할 수 없으면 **언어 모름**)을 표시합니다.

```powershell
.venv/Scripts/python.exe scripts/check_web_external_subtitles.py --offscreen
```

이 검사는 `.local/screens-66/`에 1100×720 화면(0개·여러 언어·실패·부분 성공·긴 이름·30개 파일·검색 선택/복귀)을 저장하고,
재검사 갱신과 검색 키보드 재생·복귀를 확인합니다. 실제 mpv 검사는 데스크톱 잠금 아래
`--verify`로 실행하며 실창 스크린샷은 찍지 않습니다.

모아보기(`Ctrl+2`)와 검색(`Ctrl+3`)도 웹 페이지입니다.
모아보기는 기존 `ReelControls`의 재생·반복·복습 흐름을 쓰며, 검색은 장면 재생 후
`Esc`로 돌아왔을 때 검색어·결과·선택을 보존합니다. 검색 입력의 `↓`/`Enter`는
결과로 이동하고, 목록의 `Enter`는 선택한 장면을 재생합니다.

```powershell
.venv/Scripts/python.exe scripts/check_web_reel_search.py --offscreen
.venv/Scripts/python.exe scripts/check_web_reel_search.py --verify --no-screenshots
```

첫 명령은 `.local/screens-49/`에 1100×720 웹 화면을
만듭니다(모아보기 0·2·503개·긴 메모/태그, 검색 입력 전·결과 없음·색인 준비·2개·500개 상한).
모아보기 완료 안내와 검색 오류 안내도 웹에서 확인합니다. 긴 메모는 목록에서 3줄로
줄여 보이며, 이 모아보기 페이지에 전체 메모를 펼치는 동작은 없습니다. 전체 메모는
라이브러리의 해당 영상 하이라이트 편집에서 확인할 수 있습니다.
두 번째 명령은 짧은 검증 영상을 작업 폴더에 생성해 실제 mpv 왕복, 키보드 조작,
조합 이벤트 중 검색 억제, 자동 전환·반복·복습을 검사합니다. 여러 작업자가 같은
데스크톱을 쓰는 환경에서는 반드시 관리자의 `desktop_lock.py run --owner issue-49 --`
아래에서 두 번째 명령을 실행합니다. 실제 한국어 IME 자판 입력과 다중 모니터·배율별
포커스 복귀는 별도 수동 확인 항목입니다.

웹의 일치 강조는 `search_matching.py`의 `match_spans`를 공유하고, 비동기 색인 준비는
`search_preparation.py`가 담당합니다. `search.py`는 Qt 의존성 없이 출처 이름과 결과 상한을
정의하며, 웹은 상한을 payload의 `limit`으로 받습니다.

### 새 웹 페이지 추가하는 법

웹 뷰·프로필·채널·요청 차단·썸네일·탭 이동·포커스·재생 중 설정 메뉴·상태 알림은
`web_shell.py`의 `WebShellHost`가 소유합니다. 페이지 컨트롤러는 자기 데이터·작업·갱신만 맡고
`host.register_page(self)`로 등록합니다. `MainWindow.home_page`는 화면에 표시하는 웹 호스트이고, `library_page`는 라이브러리 작업 담당입니다.
웹 컨트롤러의 QWidget 부모는 QObject 소유권과 이벤트 수명주기를 위한 것이며 자체 화면은 표시하지 않습니다.

예를 들어 새 탭을 추가할 때(아래는 `search`를 예로 듭니다) 다음 순서로 작업합니다.

1. `src/my_video_manager/web_contract.py`에 불변 `SEARCH = BridgeContract(name='search',
   interface='SearchBridge', slots=..., signals=..., aliases=..., constants=..., data_types=...)`를 선언하고
   `CONTRACTS`에 `SEARCH` 한 줄을 추가합니다. 슬롯 인수는 `Argument`, 문자열 유니온은 `TypeAlias`,
   페이지 고유 상수는 `Constant`로 선언합니다. 필요하면 새 데이터 모듈에 TypedDict를 정의하고
   `data_types`에 넣습니다. 공용 TypedDict는 소유 계약에 한 번만 등록합니다.
2. 새 `src/my_video_manager/web_search_page.py`에 QObject 브리지와 `WebPageController`를 구현합니다
   (브리지가 커지면 `web_search_bridge.py`로 분리). `@SEARCH.slot('find')`,
   `SEARCH.signal('resultsChanged')`처럼 계약으로 Qt 표면을 선언합니다.
   컨트롤러의 `tab = 'search'`, `bridge`, `refresh()`를 구현하고 초기화 마지막에
   `host.register_page(self)`를 호출합니다. 필요하면 기본 빈 함수인 `activated()`와 `deactivated()`를
   구현합니다. 호스트는 탭 이동, 재생 왕복, 호스트 표시·숨김 때 활성 컨트롤러를 바꾸며,
   이전 컨트롤러의 `deactivated()` 뒤 새 컨트롤러의 `activated()`를 호출합니다.
   `activated()`는 가볍게 유지하고, 무거운 계산은 지연하거나 취소할 수 있게 합니다(트레이 복원 때 잠깐 다른 탭이 활성화될 수 있습니다).
   재생에서 복귀할 때는 시청 종료 후 `activated()`가 호출되므로 통계 등을 다시 계산할 수 있습니다.
   활성 상태는 `is_active()`로 확인합니다. QWidget의 `isVisible()`은 자체 화면 표시 여부입니다.
   복귀 시 기본 `return_from_playback()`은 `refresh()`와 포커스 복원을 수행하며,
   라이브러리는 이를 재정의해 기존 `refresh(focus_gems=...)` 경로를 유지합니다.
   자체 포커스가 필요하면 `default_focus`와
   `focus_requested` 신호를 지정하고, 웹 첫 렌더 후 호출하는 `ready` 슬롯에서
   `self.page.frontend_ready()`를 호출합니다. 포커스 요청은 호스트가 준비될 때까지 보존합니다.
3. `web_page_registry.py`에 컨트롤러를 import하고 `WEB_PAGES`에 한 줄 등록합니다.
   새 탭이면 `web_contract.py`의 `TABS`에도 추가합니다. 모든 탭은 웹 컨트롤러로 등록합니다.
4. 새 `frontend/src/pages/SearchPage.tsx`를 작성합니다. `connectBridge()`에서
   `{ search, shell }`을 받아 생성된 공개 메서드만 사용하고, 효과를 정리할 때 신호 구독을 해제합니다.
   페이지 사이 브리지 호출은 공통 `shell` 외에는 하지 않습니다.
   페이지는 숨겨져도 마운트를 유지하므로 선택·검색어·스크롤을 보존할 수 있습니다.
   `pages/index.ts`에 컴포넌트 import와 `search: SearchPage` 한 줄을 추가합니다. 웹 페이지만 등록하고 `null` 항목은 두지 않습니다.
5. `.venv/Scripts/python scripts/generate_web_types.py`로 재생성한 뒤 `--check`, 전체 pytest,
   `frontend/`의 `npm run lint`, `npm run typecheck`, `npm run build`를 실행합니다.
   `scripts/check_web_library.py`로 1100×720 화면·단축키·Qt/mpv 왕복도 확인합니다.
   스크린샷은 `--offscreen`으로 찍고, 실창 입력 검사는 `--no-screenshots`로 캡처 없이 실행할 수 있습니다.

호스트·생성기·`App.tsx`·`bridge.ts`·`ui.py`는 새 페이지 때문에 고칠 필요가 없습니다.
채널 이름은 `TABS`의 `library`, `reel`, `search`, `queue`, `statistics`, `folders`, `settings`와 같고,
공통 객체만 `shell`입니다. 통계 페이지도 같은 등록부를 사용합니다.
`tests/test_web_generator.py`는 예시 계약을 앞·중간·뒤에 추가해도 기존 페이지 출력이 그대로인지,
`tests/test_web_pages.py`는 새 컨트롤러의 브리지·갱신·포커스 연결과 양쪽 등록부 일치를 확인합니다.
탭 누락·중복은 Qt 시작 또는 테스트에서 실패합니다. 웹 등록부 오타는 typecheck가, Python 등록부와의 누락·불일치는 계약 테스트가 검출합니다.
추가만 하는 Python·웹 등록부 두 파일에는 `.gitattributes`의 `merge=union`을 적용해 양쪽 추가 항목을 합칩니다.
`web_contract.py`는 일반 병합을 유지합니다. 새 계약 선언·`CONTRACTS` 항목의 추가 충돌은 양쪽을 보존하고
`CONTRACTS`는 하나의 튜플로 합칩니다. 충돌 블록 밖의 공통 꼬리 부분까지 확인해 각 계약 선언이 완전한 문장이 되게 합니다.
기존 계약의 같은 슬롯·신호·상수를 양쪽에서 수정했다면 내용을 검토해 하나로 결정합니다.
dict의 중복 키가 조용히 덮어써질 수 있으므로 계약 파일에 union 병합을 적용하지 않습니다.
생성 파일 충돌은 원본 계약을 합친 뒤 생성기로 다시 만듭니다.
`CONTRACTS`, Python·웹 등록부는 한 줄에 한 항목을 유지합니다.
공용 JSON 직렬화는 `web_json.py`, 셸 데이터는 `web_shell_data.py`가 소유합니다.
생성 파일은 직접 수정하지 않습니다. 페이지 객체로 나뉘어 `library` 신호 접두어는 기술적으로
필수가 아니지만 기존 호출부와 병렬 작업의 호환성을 위해 유지합니다.

### 웹 대화상자 (#53)

태그 편집·모든 태그 관리, 시리즈, 하이라이트 목록·편집,
자막 만들기·원어 지정, 자막 검수·구간 재생성·SRT 저장, 번역 CLI 선택을 웹으로 엽니다.
`web_dialogs_entries.py`의 진입 어댑터는 웹 대화상자만 엽니다. 제목 변경·영상 제외도 웹에서 처리하며, 제외 목록·관심 없음 복원은 폴더 관리의 해당 구역으로 이동합니다.
번역 CLI 선택지와 표시 이름은 `translation_cli.TRANSLATION_CLI_CHOICES`에서 읽습니다.

`web_dialogs_host.py`는 기존 웹 뷰 한 개의 대화상자 수명과 포커스를 관리하고,
`web_dialogs_models.py`는 `AppCore` 공개 메서드를 호출합니다. `web_contract.py`의
`DIALOGS` 계약을 생성하면 웹 `DialogsLayer`가 같은 데이터·명령을 사용합니다.
태그 변경은 즉시 저장하고, 나머지 편집은 저장·취소로 확정합니다. 태그 후보를
명시적으로 선택하지 않은 Enter는 입력한 이름을 추가하며, IME 조합 Enter는 추가하지 않습니다.
검수 중에는 줄 ID·선택·스크롤을 유지하고 재생성 대기·진행 중에는 수정을 잠급니다.
부분 번역 내보내기는 경고 시점의 스냅샷을 Windows 기본 `QFileDialog`로 저장합니다.

웹 셸이 보일 때는 페이지 위의 React 모달 층을 사용합니다. 재생처럼 셸이
숨겨진 경우에는 같은 웹 뷰를 메인 창 소유의 window-modal `QDialog`에 잠시 옮깁니다.
mpv는 계속 재생하며 검수 장면 이동도 가능합니다. 닫으면 뷰를 원래 레이아웃에 돌려놓고
페이지 상태를 복원하며, 재생 중이면 `PlaybackPage.focus_content()`를 호출합니다.
React가 보고한 콘텐츠 크기로 컨테이너를 맞추고 메인 창 크기를 넘지 않습니다.
숨은 페이지의 레이아웃 크기는 고정해 가상화 격자의 재측정·스크롤 이동을 막습니다.
셸이 다시 보이면 열린 대화상자를 유지한 채 뷰를 즉시 셸로 돌려놓습니다.
추가 `QWebEngineView`, 프로필, 페이지를 만들지 않습니다.

`ShellModals`는 페이지 구현을 수정하지 않고 열린 `dialog`·`alertdialog`를 감지해
`dialogs.modalState()`로 알립니다. 실제 모달만 `Ctrl+1~7`·`Alt+S`의 셸 동작을 막고 키 이벤트는 입력·키 캡처로 전달하며,
Esc·Tab·Enter는 해당 모달이 처리합니다. 탐색·재생 진입·웹 재로드는 이전 모달 상태를 비웁니다.
`highlight-range`는 웹 구간 표시와 Qt 재생 진행 막대가 함께 쓰는 의미 색 토큰입니다.

검사는 독립 합성 데이터만 만들며 사용자 라이브러리를 변경하지 않습니다.
생성한 임시 영상·DB는 종료 시 정리합니다. 공용 모달 검사는 `frontend/checks/`에서
실제 Radix Dialog·Popover와 `ConfirmDialog`를 별도로 빌드해 사용하며 제품 번들에는 포함하지 않습니다.

시청 기본값은 `AppCore(viewing_settings=ViewingSettings(...))`로 주입합니다.

`playback-restart`까지는 구간을 연결하지 않습니다. 화면은 이 보고를 UI 스레드에서

후속 하이라이트 모아보기에서도 같은 재생 연결을 사용할 수 있습니다.

태그 공개 API는 `AppCore.tags(prefix="")`, `create_tag(name)`, `rename_tag(tag_id, name)`,

붙은 태그를 읽고 `remove_video_tag(video_id, tag_id)`·`remove_highlight_tag(highlight_id, tag_id)`로 뗍니다.
후속 기능은 `videos_for_tag(tag_id)`와 `highlights_for_tag(tag_id)`로 대상 객체를 조회할 수 있습니다.
태그별 영상은 제목·ID 순, 하이라이트는 영상 ID·시작 시각·ID 순입니다.

```powershell
.venv/Scripts/python -m pytest -n auto -q
```

영상 지문은 `v1:파일크기:SHA256`입니다. 앞·중앙·뒤에서 각각 최대 64 KiB를 읽습니다.
동일 내용의 복사본은 하나의 영상과 여러 위치로 저장됩니다. 전체 파일 해시가 아니므로
같은 크기이고 샘플 부분이 같은 파일은 구별하지 못할 수 있습니다(ADR-0002의 절충).
제목은 최초 등록 위치의 확장자를 제외한 파일 이름입니다.
파일 확장자에 제한을 두지 않고 ffprobe가 실제 영상 스트림과 양수 길이를 확인합니다.
GIF·정지 이미지 형식과 단일 프레임, 첨부 그림은 새 영상으로 등록하지 않습니다.
새 영상에는 최소 길이 필터를 적용합니다. 경로·파일 크기·나노초 수정 시각이 그대로인
등록 위치는 미디어 정보와 지문을 다시 읽지 않으며, 비영상 파일도 ffprobe로 다시 읽지 않습니다.
크기나 수정 시각이 달라지면 재판정합니다. 크기와 수정 시각까지 강제로 동일하게 유지한 변경은 감지하지 못합니다.
검사를 마치면 이번 감시 폴더 범위에서 사라진 경로의 비영상·짧은 파일 캐시를 정리합니다.
검사 범위 밖과 접근 오류로 확인하지 못한 폴더의 캐시는 유지합니다.
손상된 영상이나 썸네일 생성 실패는 검사 결과에 알리고 나머지는 계속 등록합니다.
디렉터리 열거 오류도 검사 결과로 알리며 다른 폴더는 계속 검사합니다.
정션·심볼릭 링크 등 재분석 지점은 건너뛰고 이미 검사한 실제 디렉터리는 다시 들어가지 않습니다.

실시간 파일 감시는 제공하지 않으므로 파일을 옮기거나 드라이브를 연결한 뒤 **다시 검사**를 누릅니다.
기존 DB는 최초 실행 때 라이브러리 테이블을 v4로 이전합니다(`PRAGMA user_version = 4`).
영상 ID와 다른 기능 테이블은 그대로 유지하며, 이전 위치는 첫 검사에서 캐시 정보를 채웁니다.
이전 직전에는 원래 버전 DB의 자동 백업을 남깁니다. v3은 가로·세로 및 해상도 확인 상태 열을,
v4는 번역 작업의 용어집과 최근 사용 순서를 저장하는 테이블을 추가합니다.
새 등록과 파일 변경 검사 때 ffprobe의 첫 일반 영상 스트림 크기를 저장하며 display matrix와
구형 rotate 태그의 90/270도 회전을 반영합니다. 해상도 미확인 기존 영상은 유휴 시간에
한 번에 한 개씩 약 1초 간격으로 읽습니다. 재생·받아쓰기·검사가 시작되면 채우기를 취소하고,
종료·재시작 후 미처리 항목부터 이어갑니다. 파일 없음·실패 항목은 알 수 없음으로 남기며
**다시 검사** 또는 파일 다시 연결로 재시도합니다. 실패한 항목을 시작할 때마다 반복하지 않습니다.
통계의 라이브러리 구성은 짧은 변 기준 SD(<720), 720p, 1080p, 1440p, 4K 이상(≥2160),
알 수 없음 분포를 표시합니다. 각 구간의 최소값을 넘으면 해당 구간에 포함합니다.
검수 기록과 구간 요청은 별도 테이블을 쓰며 기존 테이블 구조·DB 버전은 바꾸지 않습니다.

## 라이브러리 백업과 백업 복원 (#65)

설정 → **백업**에서 Windows 저장 대화상자로 백업을 만들거나 열기 대화상자로 백업 복원을 예약합니다.
썸네일은 기본 제외이며 선택해서 포함할 수 있습니다. 생성·검사·예약은 작업자에서 실행하고 진행 상태와
실패 이유를 화면에 표시합니다. 쓰기 경합으로 제한 시간에 걸리면 재생·자막 처리를 멈추고 다시 시도하세요.
만든 시각·영상 수·앱/DB 버전의 미리보기를 확인한 뒤 위험 작업 확인을 거쳐야 예약됩니다.
**앱 다시 시작**은 기존 정상 종료 절차로 받아쓰기·번역·시청을 정리하고 같은 데이터 폴더로 다시 실행합니다.
진행 중인 백업이나 종료하지 못한 작업자가 있으면 종료를 막습니다. 적용 전에는 **예약 취소**로 취소할 수 있습니다.
마지막 시작의 적용·거부·미뤄짐 결과는 현재 예약과 따로 표시하므로 예약을 취소하거나 교체해도 확인할 수 있습니다.

`AppCore.create_backup(path, include_thumbnails=False)`는 SQLite backup API의 128페이지 단위
복사로 실행 중인 라이브러리를 ZIP 하나에 담습니다. UI에서는 작업자에서 호출합니다.
현재 시청의 저장 주기 전 진행분도 백업 사본에 반영하며 재생은 계속됩니다.
`manifest.json`에는 앱 식별자·백업 형식 버전·앱 버전·DB 버전·UTC 생성 시각·영상 수
(제외 영상 포함)·썸네일 포함 여부와 각 파일의 SHA-256, 생성 이유(`reason`)가 들어갑니다.
DB와 선택한 썸네일만 담고, 영상·모델·번역 임시 폴더·실행 잠금은 담지 않습니다.
`BackupResult.snapshot_seconds`는 DB 복사 시간이며 `max_step_seconds`는 복사 단계의 최대
경과 시간입니다. `perf_counter`로 재며 연결·디스크 I/O를 포함한 실제 읽기 잠금 시간의 상한 추정치입니다.
다른 연결의 쓰기로 남은 페이지가 늘어나면 재복사로 셉니다. **3회** 또는 **30초** 제한에서
`BackupBusyError`로 중단하고 기존 ZIP은 유지합니다. 오류의 `restart_count`와 `reason`
(`source_changed` / `deadline_exceeded`), 재생·자막 처리를 멈추고 재시도하라는 문구를 화면에 전달합니다.
453.8 MiB DB에서 일괄 복사는 UI 시청 저장을 3.15초 막았으므로 일괄 전환은 사용하지 않습니다.

`AppCore.inspect_backup(path)`는 파일 목록·SHA-256·SQLite 무결성·메타데이터를 모두 검사한
후 미리보기용 `BackupMetadata`를 돌려줍니다. 새 DB 버전, 다른 앱, 손상된 백업은 거부합니다.
추출 전에 선언된 전체 크기와 임시 디스크 여유 공간을 비교하고, 8 MiB를 넘는 썸네일과
대소문자만 다른 중복 파일 이름을 거부합니다.
`AppCore.request_backup_restore(path)`는 검증한 ZIP 사본을 데이터 폴더에 예약하고
`BackupRestoreResult.restart_required=True`와 파일 없음 위치의 다시 연결 안내를 돌려줍니다.
현재 DB나 작업 중인 받아쓰기·번역을 바꾸지 않습니다. `pending_backup_restore()`로 예약을 검사하고
`cancel_backup_restore()`로 취소할 수 있습니다. 화면의 재시작은 기존 정상 종료 절차로 작업자를
종료한 다음 새 프로세스를 시작합니다.

시작 경로는 `SingleInstance` 잠금을 잡은 뒤, `AppCore`나 DB 연결을 만들기 전에
`backup.apply_pending_backup_restore(database, instance=instance)`를 호출합니다. 다시 검증하고
임시 DB에서 필요한 이전을 완료한 다음, 현재 DB와 썸네일의 자동 백업을 먼저 남깁니다.
이전·압축·디스크 쓰기가 실패하면 현재 라이브러리는 유지됩니다. 썸네일은 기존 파일을
덮어쓰지 않고 충돌 시 새 이름을 사용하며 DB 파일의 `os.replace`가 유일한 커밋 지점입니다.
기존 WAL은 교체 전에 체크포인트합니다. DELETE 모드의 열린 파일은 Windows의 이름 바꾸기 실패로
교체를 막으며, 파일 사용/접근 권한 오류로 분류합니다.
교체 직전에 예약을 `.applying`으로 옮겨 교체 후 청소 실패나 비정상 종료가 다음 시작에서
같은 백업을 재적용하지 않게 합니다. 이 짧은 구간에서 강제 종료되어 원래 DB가 남은 경우에는
원본 ZIP 또는 남은 `.applying` 파일을 다시 `request_backup_restore`에 전달합니다.
24시간 지난 내부 `.restore-*` 임시 폴더와 `.applying`은 다음 시작 때 최선 노력으로 청소합니다.
현재 예약과 `.rejected` 파일은 자동 청소하지 않습니다.
없어진 영상 위치는 파일 없음으로 돌아갑니다. **외장 드라이브를 잠시 뺀 경우도 왕복 동일성의 예외**입니다.
드라이브를 연결하거나 새 감시 폴더를 추가해 다시 검사하면 내용 지문으로
기존 기록에 다시 연결됩니다. 썸네일을 제외한 백업은 기존 썸네일 캐시를 유지합니다.

손상된 백업과 임시 DB 이전 실패는 예약을 `*.rejected`로 격리하고 현재 데이터로 정상 시작합니다.
공간 부족·파일 사용 중 등 일시적 실패는 예약을 유지한 채 현재 데이터로 시작하고 다음 시작에 재시도합니다.
`__main__`이 결과를 `set_backup_restore_startup_result`로 전달하며 `AppCore.backup_restore_status()`는
ZIP을 다시 추출하지 않고 `status`(`scheduled` / `applied` / `rejected` / `deferred`),
`error_kind`, `error_message`, `rejected_path`를 조회합니다. 반복 실패는 `cancel_backup_restore()`로 취소합니다.
현재 DB 손상과 공간 부족 등이 겹쳐 현재 데이터로도 열 수 없으면 웹 셸 대신 짧은 Qt 복구 화면을 엽니다.
단일 인스턴스 잠금을 유지하면서 **다시 시도**, **예약 취소**, **데이터 폴더 열기**를 사용할 수 있습니다.
예약을 취소해도 원본 데이터·보존 사본은 지우지 않습니다. 읽기 전용 파일은 속성을 해제하라는 구체 안내를 유지합니다.

`migrate_library`는 버전을 올리기 전에 `backup_before_migration`을 호출합니다.
#64에서는 `LIBRARY_DB_VERSION`을 올리고 해당 이전 DDL을 추가하면 이 연결 지점을 그대로
사용할 수 있습니다. 빈 새 DB에는 자동 백업이 생기지 않습니다. 자동 백업은 데이터 폴더의
`backups/`에 최근 **5개**를 보존하며 `AppCore.automatic_backups()`로 최신순 경로를 얻습니다.
백업 복원 전 자동 백업은 썸네일을 포함하고, DB 이전 전 자동 백업은 DB만 담습니다.
오래된 ZIP 삭제 실패는 작업을 막지 않고 다음 생성 때 다시 정리합니다. 생성 자체가 실패하면 이전을
막으며 `BackupStorageError.kind`(`disk_full` / `file_in_use` / `storage_error`)와 조치 안내를 돌려줍니다.
설정의 자동 백업 목록은 시각·크기·이유를 표시하고 폴더 열기와 복원 미리보기를 제공합니다.
`AppCore.backup_inventory()`는 ZIP을 추출하지 않고 목록 메타데이터와 예약 존재 여부만 읽습니다.
자동 백업 이유는 `before_restore` / `before_migration`이며 이전 백업에 이유가 없으면
‘백업 복원 또는 DB 형식 변경 전(상세 이유 기록 없음)’으로 표시합니다. 이전 ZIP도 그대로 검사·복원됩니다.
`scripts/check_web_backup.py --offscreen`은 1100×720 화면과 키보드·진행·실패·예약 취소 흐름을 검사합니다.
`--startup applied|rejected|deferred`로 마지막 시작 결과를 각각 별도 프로세스에서 검사합니다.

## 직접 확인할 항목

자동 테스트는 실제 mpv 화면을 포함하지 않습니다. 변경 후 아래를 실제 창에서 확인합니다.

- 한글·공백이 있는 감시 폴더와 하위 폴더를 추가해 썸네일과 제목이 표시되는지.
- MKV/HEVC 영상 및 AC3·DTS 음성이 창 안에서 영상·소리와 함께 재생되는지.
- 마우스 더블클릭과 방향키 + Enter로 영상을 열 수 있는지.
- 재생 중 표의 모든 키, Esc로 목록 복귀, 다른 앱에 포커스를 옮긴 뒤 키 입력이 이 앱을 조작하지 않는지.
- 종료·재실행 후 라이브러리와 감시 폴더가 유지되는지.
- 감시 폴더 해제·직접 추가·파일 다시 연결·제외와 복원·제목 변경·최소 길이 설정이 다음 실행에도 유지되는지.
- 테스트 파일을 이름 변경·이동하거나 치운 뒤 검사하면 같은 영상으로 연결되거나 파일 없음으로 표시되는지.
- Insert/Delete 표시가 진행 막대와 목록에 반영되고 Home/End로 이동하는지.
- 열린 구간에서 Esc·창 닫기를 실행한 뒤 다시 열면 마지막 위치까지 저장되어 있는지.
- 하이라이트 목록에서 한글 메모, 시각 편집, 삭제와 재실행 후 보존을 확인하고 편집 중 Delete/Home/End가 글 편집에만 쓰이는지.
- 영상과 하이라이트의 태그 입력에서 자동 완성, Enter 추가, Tab 이동·Space 버튼 조작과 태그 떼기가 동작하는지.
- 전체 태그 이름 변경·삭제가 양쪽에 반영되고, 태그 필터와 재실행 후 저장이 유지되는지.
- 실제로 5% 이상 본 뒤 목록의 보다 만 표시와 3초 전 이어보기, 다 본 뒤 처음부터 재생되는지.
- 앞으로 건너뛰기·되감기·배속·일시정지를 섞어도 시청 비율과 마지막 정지 위치가 구별되는지.
- 테스트용 데이터로 재생 중 강제 종료한 뒤 마지막 저장분과 이어볼 위치가 복구되는지.
- 영상에서 자막 요청 → 재생 중 처리 완료 → `/` 표시 전환 → 원어 지정 후 다시 생성되는지.
- 번역 전 `.` 안내, 번역 완료 후 `.` 원어/한국어 전환과 `/` 표시 전환이 각각 동작하는지.
- 번역 CLI 선택을 바꾼 뒤 재시작해도 유지되고, 실패·보류 재시도가 저장한 묶음부터 이어지는지.
- 긴 실제 영상과 평소 배속에서도 GPU 받아쓰기를 함께 켰을 때 재생이 매끄러운지.

- 번호 붙은 영상의 시리즈 표시와 편집 저장·재검사, 새 화 추가 후 순서를 확인하는지.
- PgUp/PgDn으로 시리즈와 일반 목록을 이동하고 경계에서 유지되며 이어보기·열린 구간 종료가 적용되는지.
- 모아보기 태그 필터와 Home/End 항목 이동, 같은 영상의 자동 전환·반복이 깜박임 없이 이어지는지.
- 지점 길이·구간 끝·영상 EOF(마지막 10초 안의 지점 포함)에서 다음 항목·영상으로 자동 전환되는지(webm·DTS mkv 포함).
- PgDn은 다음 영상의 첫 하이라이트, PgUp은 현재 영상의 첫 하이라이트로 이동하고 이미 첫 항목이면 이전 영상으로 이동하는지.
- 한국어 자판의 `₩`(백슬래시) 키로 반복을 켜고 끌 수 있고 상태 표시가 바뀌며, 끄거나 모아보기를 나갈 때까지 유지되는지.
- 항목 전환에도 배속·자막 표시가 유지되고, 원어/번역 선택은 같은 영상에서 유지되며 다른 영상은 원어부터 시작하는지.
- 모아보기 중 Enter·방향키·쉼표·슬래시가 동작하고, Insert/Delete로 만든 하이라이트가 목록 갱신 뒤 나타나며 열린 구간은 전환 때 닫히는지.
- Esc가 재생 → 모아보기 목록 → 라이브러리 순서로 돌아가고, 3초 재생 또는 짧은 항목 완주 뒤 마지막 복습 시각만 갱신되며 다 봄·보다 만·이어볼 위치는 그대로인지.
- 제외한 영상의 하이라이트는 숨겨지고 되돌리면 다시 나타나며, 일반 재생의 Home/End·PgUp/PgDn 동작은 유지되는지.

ffmpeg/ffprobe를 찾지 못하면 설치 후 새 터미널을 열거나 PATH를 확인하세요.
앱은 winget 기본 설치 경로도 탐색하므로 설치 직후 기존 터미널에서도 실행할 수 있습니다.
`libmpv-2.dll` 오류는 `scripts/install_libmpv.py`를 다시 실행하고 Python과 DLL이 모두 x64인지 확인하세요.

### 자막 검수와 SRT 내보내기

라이브러리나 재생 화면의 **자막 검수 / SRT 내보내기**에서 원어·번역을 나란히 봅니다.
방향키로 줄을 고르고 Enter 또는 클릭으로 그 장면에 이동합니다. 같은 영상은 탐색하고,
일시정지 중이면 재생을 재개하며, 재생 중인 영상이 없으면 선택한 시각부터 재생합니다.
모아보기 중 줄을 선택하면 그때까지의 복습 기록을 유지하고 모아보기를 끝낸 뒤 일반 시청으로
선택한 줄부터 재생합니다. 같은 영상의 일반 재생 중에는 기존 시청을 그대로 이어갑니다.
Tab으로 수정·재생성·내보내기 버튼에 이동하고 Space로 실행합니다. Esc는 검수 창을 닫습니다.
수정 대화상자에서는 재생 키가 텍스트 입력을 방해하지 않습니다.

**원어 줄 수정**은 줄 ID를 유지하며 그 줄만 다시 번역합니다. 한국어·알 수 없는 원어는
번역하지 않습니다. **번역 줄 수정**은 해당 줄을 검수됨으로 표시하고 자동 재번역·한도 보류
후 재개·직접 재시도에서도 보호합니다. 직접 고친 번역의 원어를 바꿀 때만
**직접 고친 번역이 덮어써집니다** 확인 후 보호를 해제하고 다시 번역합니다.
원어 수정과 번역 직접 수정은 각각 표시하며, 전체 재생성 경고의 줄 수는 중복 없이 셉니다.
원어 수정은 해당 줄의 번역 대상만 초기화합니다. 다른 대상·완료 묶음과 영상의 번역 대기열
상태·오류·재시도 시각·한도 횟수는 유지하며, 실패 상태는 직접 재시도해야 합니다.
진행 중인 번역 요청을 교체하면 옛 응답은 버리고 새 요청은 대기로 돌립니다.
옛 요청이 뒤늦게 한도 응답을 받아도 새 요청의 상태·한도 횟수는 바꾸지 않고, CLI 계정의 15분 보류만 유지합니다.
재생성 대기·진행 중에는 줄 수정을 막아 생성 결과가 새 검수를 지우지 않게 합니다.

**구간 다시 생성**에 시작·끝 시각(초)을 입력합니다. 경계에 걸친 줄의 중복이나 유실을 막기 위해
겹치는 모든 줄의 시작·끝을 덮도록 범위를 넓힙니다. 새로 겹치는 줄이 없어질 때까지 반복하되
영상 길이를 넘지 않으며, 대화상자에 실제 받아쓸 범위를 표시합니다. 이 범위와 겹치는 줄은
모두 교체하고, 끝 시각에 시작하거나 시작 시각에 끝나는 줄은 유지합니다.
받아쓰기 어댑터에 `start`와 `duration`을 넘기며 FFmpeg가 해당 구간만 디코드합니다.
반환 시각은 구간 상대값이고 확장 범위로 자른 뒤 저장 때 시작 시각을 더합니다. 새 줄은 새 UUID를 받고
이전 줄의 번역·검수 기록은 CASCADE로 지웁니다. 새 줄만 추가 번역 대상으로 넣고,
기존 미완료 번역은 보존합니다. 음성이 없으면 해당 구간의 기존 줄만 제거합니다.
구간 교체도 번역 보류·실패 상태, 재시도 시각·오류·한도 횟수와 완료 묶음을 보존합니다.
구간 요청은 직접 요청 우선순위와 요청 순서로 등록하며, 진행률은 실제 받아쓰기 범위를 기준으로
표시합니다. 대기·받아쓰는 중에는 줄 수정을 막고, 취소나 앱 재시작 시 기존 자막을 유지합니다.
원어와 원어 지정 여부는 구간 재생성으로 바뀌지 않습니다.
`UNIQUE(transcript_id, ordinal)`을 유지하기 위해 기존 ordinal을 먼저 임시 음수로 옮긴 뒤
최종 순서로 돌립니다. 삭제·삽입·순서 변경·번역 요청은 한 트랜잭션이므로 실패하면
기존 원어·번역·검수가 유지됩니다. 취소·강제 종료한 구간 요청은 다음 실행에서 다시 처리합니다.
구간 재생성 실패 시 검수 창의 **구간 다시 생성**으로 재시도하도록 안내합니다.
대기열의 **실패 항목 모두 재시도**도 실패한 구간 요청은 같은 구간으로 다시 처리하며 전체를 재생성하지 않습니다.
**전체 다시 생성**은 사라지는 검수 줄 수와 원어·번역 교체 경고를 확인한 뒤 진행합니다.

**원어 SRT 저장 / 번역 SRT 저장**에서 저장 대화상자로 위치를 고릅니다.
기본 폴더는 영상 폴더, 기본 이름은 `영상제목.원어코드.srt`와 `영상제목.ko.srt`입니다.
알 수 없는 원어는 `und`, Windows 파일 이름에 쓸 수 없는 문자는 `_`를 사용합니다.
파일 없음 영상은 홈 폴더를 제안하며, 자막 검수와 내보내기는 계속 가능합니다.
사용자가 저장을 선택할 때만 파일을 쓰며 영상 옆에 자동 생성하지 않습니다.
Windows 플레이어가 한글을 ANSI로 오인하지 않도록 **UTF-8 BOM**을 포함합니다.
기존 `transcript_srt`로 1부터 연속 번호와 `HH:MM:SS,mmm` 시각을 생성합니다.
줄 수정과 SRT 생성은 줄바꿈을 LF로 통일하고 각 줄의 앞뒤 공백과 빈 줄을 제거합니다.
번역이 일부만 끝났거나 재번역 중이면 **N줄 미번역 · 재번역 대기 N줄** 확인 후 저장된 번역 줄만
내보냅니다. 내보낼 줄이 없으면 저장을 막습니다.
완료 전이라도 저장된 번역 묶음은 목록·내보내기에서 볼 수 있고, 재번역 중에는 기존 번역을
우선 표시합니다. 내보내기 확인 당시의 스냅샷을 저장하므로 안내한 미번역 수와 파일이 일치합니다.

검수 로직은 `review.py`, 웹 화면은 `frontend/src/dialogs/DialogsLayer.tsx`에 있습니다. 화면은 웹 브리지를 통해 `AppCore` 공개 메서드를
호출합니다. 검색 색인은 이 기능이 별도로 갱신하지 않으며, 검색 모듈의 DB 트리거를 따릅니다.
`tests/test_review.py`는 줄 ID 유지·선택 재번역·검수 보호·동시 응답·구간 경계와 줄 수 변화·
실패와 취소·전체 교체·부분 SRT와 명시적 저장을 공개 코어 API로 검증합니다.

### 웹 자막 대기열과 자동 규칙

`Ctrl+4` 또는 트레이의 **대기열 보기**로 웹 대기열을 엽니다.
처리 상태의 목록에서 ↑/↓·Home/End로 선택하고 Tab으로 버튼에 이동해 Space로 실행합니다.
상태 필터, 앞당기기, 빼기, 실패 항목 모두 재시도, 선택한 번역 보류 재시도는 `AppCore` 작업을 사용합니다. 재시도에서 건너뛴 영상은 제목과 이유로 표시합니다.

자동 자막 규칙에서 폴더 또는 태그와 원어를 골라 저장합니다. **기존 영상도 추가**에서
**예**는 규칙을 저장하면서 기존 후보도 추가하고, **아니요** 또는 Esc는 규칙만 저장합니다.
기본 포커스는 아니요입니다. 원어는 자동 감지 또는 언어 코드를 입력할 수 있습니다.

`web_queue_page.py`는 활성 페이지에서만 500ms 주기로 조회합니다. 변경된 행·삭제 ID만 보내며
순서와 개수는 달라졌을 때만 보냅니다. 웹은 행별 구독을 사용해 진행률 변화로 다른 행을
다시 렌더하지 않습니다. 큐 도메인과 공개 작업은 그대로 사용합니다.

```powershell
.venv/Scripts/python scripts/check_web_queue.py --offscreen
.venv/Scripts/python scripts/check_web_queue.py --verify
```

`--offscreen`은 1100×720 웹 이미지와 300행 측정 결과를 `.local/screens-50/`에 저장합니다.
`--verify`는 캡처 없이 실제 WebEngine 포커스·키보드·확인 대화상자·트레이 경로를 검사합니다.
공유 데스크톱에서는 관리자의 `desktop_lock.py run --owner issue-50 --` 아래에서 실행합니다.
측정은 같은 AppCore 조회에 첫 행 진행률만 바꾸며, DB 포함 비용·표시 계층 비용·웹 DOM 반영과
다음 프레임 대기 시간을 구별합니다. 실 OS 한국어 IME 후보창과 시스템 트레이 메뉴의 실제 클릭은
사람이 직접 확인합니다. 합성 composition 검사는 조합 중 저장 방지만 확인합니다.

자동 규칙 확인 중 페이지가 비활성화되면 확인창을 닫고 저장하지 않습니다. 편집하던 대상·원어는
보존하며, 복귀해 다시 저장할 수 있습니다. 확인창이 열려 있는 동안에는 공용 대화상자 계층이 셸 단축키를 차단합니다.
